# Искенди · гостевое табло

Адаптивный интерфейс дюрюмной: первый ввод номера заказа, личные заказы,
общее табло, статусы, оценка эмоцией, помощь, адрес, расписание и Telegram.
Телефон, планшет и компьютер используют одну модель данных и один источник опроса API.

## Быстрый запуск

Нужны Node.js 24.19 и npm 11 (версии закреплены в `.nvmrc` и `package.json`).

```sh
npm ci
npm run dev:mock
```

Откройте [локальный интерфейс](http://127.0.0.1:5173/).
Для выбора тестового состояния откройте
[сценарии](http://127.0.0.1:5173/dev/scenarios.html).

Тестовые номера: **112** — готовим, **102** — готово,
**997 / 998 / 996** — выданы. Доступны все пять эмоций и повторное открытие черновика.
Mock-режим использует синтетические данные и не отправляет запросы в настоящий ресторан.

Для проверки с телефона в той же Wi-Fi сети:

```sh
npm run dev:mock -- --host 0.0.0.0 --port 5177
```

В адресе замените `127.0.0.1` на локальный IP компьютера. Начать с пустой формы:
`http://<локальный-IP>:5177/dev/scenario.html?preset=entry`.
Обычная перезагрузка сохраняет результат; повторный выбор сценария сбрасывает только данные стенда.

## Проверки

```sh
npm run browsers:install
npm run verify
npm run format:check
npm audit
```

Последний полный прогон перед публикацией: **750 unit/component**, **573 браузерных**
проверки прошли; **40** сценариев пропущены по условиям платформы.
`verify` включает TypeScript, ESLint, семантические токены, тесты, сборку и бюджет размера.
Проверки запускаются также в GitHub Actions. На реальном iPhone продукт проверял владелец;
последние исправления дополнительно проверены в браузерной эмуляции.

Витрина компонентов: `npm run dev:kit`, затем `http://127.0.0.1:5174/dev/kit.html`.

## Подключение API и границы реализации

Сборка предназначена для размещения рядом с существующим бэкендом
[Greatjaaack/iskendy](https://github.com/Greatjaaack/iskendy).
В приложении только относительные `/api/...`; новая гостевая часть обслуживает `/` и `/board`.
`/tv`, `/staff` и `/stats` сохраняют legacy-загрузчик. Бэкенд, его авторизация и service worker не менялись.

`npm run dev` требует отдельно подготовленного локального бэкенда на порту 8080.
`npm run build` создаёт локальную сборку и архив; команда ничего не публикует и не развёртывает.

Отправка файлов и сообщения управляющему ожидают отдельного backend-контракта:
интерфейс сохраняет ввод и показывает реальное ограничение, не имитируя доставку.
Поведение уведомлений и звука зависит от разрешений и возможностей браузера.
Реальная интеграционная проверка `npm run test:e2e:real` требует локального Docker,
закреплённого backend-снимка и тестового образа; это отдельный прогон, не часть `verify`.

## Устройство проекта

- `src/` — интерфейс, доменная логика, хранение заказов и API.
- `tokens/` — исходные семантические токены.
- `tests/` — компонентные, модульные, браузерные и интеграционные проверки.
- `dev/` — локальная витрина и выбор синтетических сценариев; в production не входят.
- `legacy/` и `public/sw.js` — сохранённый контракт старого приложения.
- `docs/` — архитектура, API, решения и история проверок.
