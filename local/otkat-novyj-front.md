# План отката — новый гостевой фронт на проде

Для выкатки `feature/new-guest-front` → `dev` → `main` табло. Писан 21.10.2026 заранее, до выкатки.
Перед выкаткой скопировать на сервер: `/root/backups/OTKAT-site-<дата>.md`, подставив фактические коммиты.

## Почему откат простой

| Что | Почему не страшно |
|---|---|
| База | миграций нет: новые ручки только читают `feedback` и шлют в Telegram. Старый код работает с той же базой |
| Телефоны гостей | ключи и формат `localStorage` прежние (ADR-012), заказ и подписка переживают откат в обе стороны |
| Кэш у гостей | `sw.js` без кэша и без `fetch`, HTML отдаётся с `no-cache` → после отката гость получит старый экран при следующей загрузке. Открытая вкладка продолжит опрашивать `/api/status` |
| Касса и `/stats` | и сейчас идут старым экраном (`legacy.html` = текущий экран кассы, импорт это сверяет) |
| ТВ | новый `/tv` сам переходит на старый, если не стартовал |
| `.env` | не меняется |

## Когда откатывать

| Признак | Уровень |
|---|---|
| `/api/health` не 200, контейнер не `healthy`, касса не открывается, заказы не едут | **1** сразу |
| Гости не могут подписаться на заказ или не видят статус на `/` и `/board` | **1** |
| Сломан только ТВ в зале | **3** (только `/tv`) |
| Не уходят сообщения или фото гостей (в теме 800 пусто, гости видят «не отправлено») | не откатывать: заказы работают, гость видит честную ошибку. Чинить днём, выкатить следующей ночью |
| Метрика не считает | не откатывать, чинить |

## Уровни

### 1. Всё назад за секунды — образ

Без сборки, на одном ядре не тормозит машину. Годится и днём при аварии — только по команде Арслана.

```bash
cd /root/iskendy
docker tag iskendy-app:rollback-<коммит> iskendy-app:latest
git reset --hard <коммит>
docker compose -f docker-compose.prod.yml up -d --no-build
curl -fsS https://iskendy.ru/api/health
```

`git reset` нужен, чтобы сервер и образ совпадали. GitHub `main` при этом ещё с новым фронтом — до следующей выкатки сделать уровень 2, иначе следующий `git pull` вернёт новый фронт.

### 2. Новый фронт назад в git — экран гостя старый, бэкенд новый

Днём, локально в `iskendy_site`, ночью — выкатка.

```bash
git switch dev
git checkout <коммит> -- frontend/   # прежний frontend/: index.html, sw.js, assets/
git commit -m "revert(front): гостевой экран — прежний"
```

Без `legacy.html` и `ROUTES.json` бэкенд отдаёт всё как до перехода (так сделано с `928cf84`, покрыто тестами). Новые ручки остаются, но их никто не зовёт. Полный откат кода — `git revert` коммитов `2711e49`, `e549333`, `80fe547` в обратном порядке.

Дальше обычный путь: `pytest`, `progon.py` по контейнеру, `dev` → `main`, ночная выкатка, `smoke-front.sh`.

### 3. Только ТВ назад на старый

В `frontend/ROUTES.json` поставить `"/tv": "legacy"` → бэкенд отдаст `legacy.html`, то есть старый ТВ. Коммит в `dev`, ночная выкатка. Гостевые экраны не трогает.

Правильно — то же самое в `src/boot/routes.ts` фронта и новый импорт; иначе следующий импорт вернёт новый ТВ.

### 4. База — только если испорчены данные

Не нужна при откате кода. Если данные действительно испорчены:

```bash
docker compose -f docker-compose.prod.yml stop
# вернуть /root/backups/site/pre-<дата>.db в том iskendy_app-data как /data/iskendy.db
docker compose -f docker-compose.prod.yml up -d --no-build
```

Заказы и отзывы между снимком и откатом пропадут — сверить с числами из шага 4.
