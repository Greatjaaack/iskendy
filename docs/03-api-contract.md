# 03 · Контракт API

**Источник правды:** код бэкенда <https://github.com/Greatjaaack/iskendy>, файлы `backend/main.py` и `backend/db.py`. Первоначально сверено с `7ab20f0`; 08.10.2026 повторно проверено на
неизменённом `166f35d63366a0da6551158fee4f2ba9760473c5` в синтетической Docker-копии (docs/29). 12.10.2026 сверено с `a0dc17a` (изменён только лендинг legacy) — docs/reviews/2026-10-12-full-review.md §4.

Этот документ — сводка для фронта. Если код бэкенда расходится со сводкой, прав код. Поправь документ и отметь это в PR.

## 1. Общие правила

- **Origin:** тот же, что у страницы. Пути относительные (`/api/...`), CORS не нужен.
- **Формат:** JSON, `Content-Type: application/json` для тел запросов.
- **Время:** часовой пояс ресторана, считает сервер.
  - `date` — `YYYY-MM-DD`;
  - метки времени — ISO-8601 со смещением (`2026-10-07T13:05:12+03:00`);
  - `now` в `/api/status` — `HH:MM`, время сервера.

  Деловую дату на часах телефона не вычислять.
- **Ошибки HTTP** (FastAPI `HTTPException`):

  | Код | Тело | Когда |
  |---|---|---|
  | 401 | `{"detail": "Нужна авторизация" \| "Сессия завершена" \| "Неверный пароль"}` | Касса |
  | 409 | `{"detail": "Касса уже открыта на другом устройстве…"}` | Касса |
  | 422 | `{"detail": [{"type", "loc", "msg", …}]}` | Тело не прошло валидацию Pydantic |
  | 429 | `{"detail": "Слишком много запросов, попробуйте через минуту"}` | Лимит |
  | 5xx | Может быть не JSON (ответ прокси Caddy) | Сбой |

- **Бизнес-ошибки** приходят с **HTTP 200** в виде `{"ok": false, "reason": "...", "message": "..."}`. `message` — готовый текст для гостя от сервера: использовать, если в Figma нет своего текста для этой причины.

| `reason` | Текст сервера |
|---|---|
| `not_found` | Не нашли такой заказ за сегодня. Проверьте номер на чеке |
| `not_served` | Заказ ещё готовится — оцените, когда заберёте |
| `already` | Спасибо, отзыв по этому заказу уже принят |
| `expired` | Время истекло, но оценку мы записали — спасибо |
| `unknown_feedback` | Не нашли эту оценку — оцените заказ заново |
| `wrong_token` | Не получилось дописать отзыв — оцените заказ заново |
| `locked` | Отзыв уже отправлен — спасибо! |
| `taken` | Этот номер уже отслеживают с другого телефона |
| `too_many` | Слишком много заказов с одного телефона за сегодня |
| `not_claimed` | Оценить заказ можно с того телефона, на котором вы за ним следили |

## 2. Эндпоинты гостевого фронта

### `GET /api/status` — табло

Публичный, без лимита. Опрашивается владельцем опроса (ADR-004).

```jsonc
{
  "date": "2026-10-07",
  "orders": [
    { "number": 112, "status": "preparing",
      "acceptedAt": "2026-10-07T13:05:12+03:00", "readyAt": null, "servedAt": null }
  ],
  "servedCount": 41,                          // выдано за день
  "updatedAt": "2026-10-07T13:07:40+03:00",   // или "" если изменений не было
  "now": "13:08"
}
```

- `orders` — только активные заказы, отсортированы по номеру.
- `status ∈ {open, preparing, ready}`. Гостю `open` показывается как «Готовим».
- `readyAt` и `servedAt` — `string | null`.
- `number` обычно целое, но `db.kassa_number` (на `a0dc17a`) сохраняет номер продажи Saby Presto **строкой**, если в нём не только цифры, и не ограничивает целые сверху. Фронт разбирает заказы по одному и пропускает строки, которые гость не может ввести (1–100000), чтобы не ронять всё табло (ревью 2026-10-12, API-02). Как показывать такие номера — Q-16.

### `GET /api/feedback/config` — настройки воронки

Публичный, без лимита. Запрашивается один раз за визит.

```jsonc
{
  "promptDelaySec": 180,
  "links": {
    "yandex": "https://…",
    "2gis": "https://…",
    "telegram": "https://…",
    "vk": "https://…",
    "instagram": "https://…"
  }
}
```

Любой ключ в `links` может отсутствовать: сервер не отдаёт пустые ссылки. Нет ссылки — нет кнопки. Перед выводом проверить, что схема `https:`.

### `POST /api/guest/claim` — закрепить номер за телефоном

Лимит: корзина `k`, 10 в минуту **на IP** (весь зал), на проверенном `166f35d`.
Исторический BUG-01 исправлен владельцем backend; см. §4.

```jsonc
// запрос
{ "number": 112, "guest": "<iskendy_guest>" }  // number: 1..100000; guest ≤ 40 символов

// ответ
{ "ok": true, "claimToken": "<до 64 символов>", "number": 112 }
{ "ok": false, "reason": "taken" | "too_many", "message": "…" }
```

- **Идемпотентность:** тот же `guest` для уже закреплённого за ним номера получает **тот же** `claimToken`.
- **Лимит на устройство:** не больше `CLAIM_MAX_PER_GUEST_DAY` (сейчас 5) номеров на один `guest` за день, дальше `too_many`. Удаление карточки на телефоне квоту не возвращает.
- Заказа может ещё не быть в базе: закрепление номера, так и не появившегося в кассе, протухает на сервере (`CLAIM_PENDING_TTL_MIN`).

### `GET /api/feedback/check?number=` — можно ли оценить заказ

Лимит: корзина `r`, 120 в минуту на IP. Клиент вызывает не чаще раза в 20 с на заказ.

```jsonc
{ "ok": true, "reason": null, "number": 112, "waitSeconds": 734 }
{ "ok": false, "reason": "not_found" | "not_served" | "already", "message": "…" }
```

### `POST /api/feedback` — поставить оценку

Лимит: корзина `w`, 20 в минуту на IP, общая для `/api/feedback`, `/rate`, `/detail`.

```jsonc
// запрос
{ "number": 112, "rating": 4, "claim_token": "<claimToken>" }   // rating: 1..5

// ответ
{ "ok": true, "feedbackId": 931, "editToken": "<…>",
  "branch": "positive" | "negative",
  "number": 112, "rating": 4, "waitSeconds": 734,
  "links": { /* как в config, только при branch = positive; при negative — {} */ } }
{ "ok": false, "reason": "not_claimed" | "not_found" | "not_served" | "already", "message": "…" }
```

- `branch` считает сервер (`negative`, если `rating ≤ FEEDBACK_NEGATIVE_MAX`, сейчас 3). На клиенте порог не дублировать.
- Ссылки для экрана «Выдан» по Figma берутся из `/api/feedback/config`, а не из этого ответа (см. [01-product.md](01-product.md) §9).

### `POST /api/feedback/rate` — исправить оценку

Лимит — корзина `w`.

```jsonc
// запрос
{ "feedback_id": 931, "edit_token": "<editToken>", "rating": 5 }

// ответ
{ "ok": true, "branch": "positive", "links": { /* как в config для positive, иначе {} */ } }
{ "ok": false, "reason": "unknown_feedback" | "wrong_token" | "expired" | "locked", "message": "…" }
```

- Исправление возможно в окне `FEEDBACK_EDIT_WINDOW_MIN` (сейчас 120 мин) и только пока не отправлены детали, иначе `locked`.
- Оценка вне 1–5 отсекается Pydantic (422); ветка `ValueError` → HTTP 400 в `main.feedback_rate` на практике недостижима.
- Сверено через ASGI 07.10.2026: публичный ответ содержит только `ok`, `branch`, `links`. Поля `changed`, `was` и полный `feedback` используются внутри бэкенда и наружу не возвращаются. Исходная сводка здесь была неточной.

### `POST /api/feedback/detail` — детали отзыва

Лимит — корзина `w`.

```jsonc
// запрос — все поля, кроме идентификаторов, необязательны
{ "feedback_id": 931, "edit_token": "<editToken>",
  "tags": ["Вкус", "Скорость"],      // ≤ 12 штук; каждый обрезается до 40 символов; запятые запрещены
  "comment": "…",                     // ≤ 1000 символов
  "contact": "" }                     // ≤ 120 символов (см. Q-07)

// ответ
{ "ok": true }
{ "ok": false, "reason": "unknown_feedback" | "wrong_token" | "expired", "message": "…" }
```

Сервер склеивает теги через запятую (итог ≤ 300 символов) и при чтении делит по запятой. Тег с запятой развалится на два.

### `POST /api/guest/event` — шаг воронки

Лимит: корзина `s`, 240 в минуту на IP.

```jsonc
{ "step": "sub_ok", "session": "<iskendy_visit>", "guest": "<iskendy_guest>", "number": 112 }  // number | null
// ответ: { "ok": true | false }  — неизвестный шаг тихо не пишется
```

Допустимые `step`: `board_open`, `sub_try`, `sub_fail`, `sub_ok`, `sub_pending`, `ready_seen`, `rate_shown`, `rated`, `review_click`.

### `POST /api/client/event` — экран сообщает о себе

Лимит: корзина `c`, 30 в минуту на IP; отдельная от claim `k` на `166f35d`.

```jsonc
{ "kind": "offline" | "render" | "js", "screen": "board", "detail": "экран был без связи 240 с" }
// kind ≤ 20, screen ≤ 40, detail ≤ 300 символов. Ответ: { "ok": true }
```

### `GET /api/health`

`{ "ok": true }`. Используется только для проверок, в UI не нужен.

## 3. Лимиты запросов

Окно — 60 с, ключ — IP клиента. В зале все гости выходят через один IP, поэтому лимит считается на весь зал.

| Корзина | Лимит / мин | Эндпоинты |
|---|---|---|
| `r` | 120 | `GET /api/feedback/check` |
| `w` | 20 | `POST /api/feedback`, `/api/feedback/rate`, `/api/feedback/detail` |
| `s` | 240 | `POST /api/guest/event` |
| `k` | 10 | `POST /api/guest/claim` |
| `c` | 30 | `POST /api/client/event` |
| `l` | 10 | `POST /api/auth/login` (касса) |
| — | без лимита | `GET /api/status`, `GET /api/feedback/config`, `GET /api/health` |

Правила фронта:
1. Лимит не обходится. 429 — штатная ситуация: понятный текст «много гостей, попробуйте через минуту» и без автоповтора.
2. Число запросов минимально: `check` — не чаще раза в 20 с, `config` — раз за визит, `client/event` — не чаще раза в 60 с, шаги воронки — с дедупликацией.

## 4. Известные дефекты бэкенда (фронт обходит, бэкенд не трогаем)

### BUG-01 · Общая корзина `guest/claim` и `client/event` — исправлено владельцем backend

На историческом `7ab20f0` обе ручки вызывали `_guard(..., kind="c")`: claim — с лимитом 10, client/event — с лимитом 30. Ключ счётчика общий: `c:<ip>`.

Последствие: если за минуту с IP зала пришло 10 и более отчётов экранов, **все подписки на заказы в зале получают 429** до конца окна. И наоборот, подписки съедают лимит отчётов. Комментарий в коде и README утверждают, что корзины раздельные, но по факту это не так.

**Обход на фронте:**
- отчёты экрана — не чаще раза в 60 с с устройства, только после восстановления связи или при ошибке;
- никогда во время сценария подписки;
- `detail` короткий.

**Проверенное исправление:** на `166f35d` claim использует `k`, client/event — `c`.
На одном синтетическом IP 30 отчётов прошли, 31-й получил 429; затем 10 claim
прошли, 11-й получил собственный 429. Guest event и feedback/check продолжили
отвечать 200. Доказательство — docs/29 и http-contract-result.json.
Фронт не менял backend и сохраняет защитный троттлинг ADR-015.
Лимит claim всё ещё общий на IP зала, не на устройство; обещаний нагрузки нет.

### NOTE-01 · Уточнение ответа `/api/feedback/rate`

Прямой захват ASGI-ответа на коммите `7ab20f0` подтвердил: полного объекта отзыва в HTTP-ответе нет; см. `tests/fixtures/rate-ok.json`. Не следует строить схему по внутреннему результату `db.feedback_rate`.

## 5. Эндпоинты кассы и аналитики (фаза 8, справочно)

Все, кроме `POST /api/auth/login`, требуют `Authorization: Bearer <JWT>` активной сессии кассы (`iskendy_staff_token`). Касса одна: второй вход возвращает 409 и уходит в алерт.

| Метод | Путь | Что |
|---|---|---|
| POST | `/api/auth/login` | `{password}` → `{token}`; 401, 409 |
| POST | `/api/auth/logout` | Освободить кассу |
| GET | `/api/auth/session` | Кто за кассой |
| POST | `/api/order` | `{number}` → завести вручную («готовится») |
| POST | `/api/order/status` | `{number, status}` |
| POST | `/api/order/delete` | `{number}` |
| GET | `/api/order/served?limit=` | Выданные сегодня |
| POST | `/api/order/revert` | `{number}` → вернуть выданный в «готово» |
| POST | `/api/day/reset` | Убрать активные с табло |
| GET | `/api/events?date=` | Журнал событий |
| GET | `/api/stats/days`, `/api/stats/range?dates=`, `/api/stats/orders?dates=`, `/api/stats/feedback`, `/api/stats/guest?dates=` | Аналитика |
| GET/POST | `/api/feedback/list?date=&status=`, `/api/feedback/status` | Инбокс отзывов |
| GET | `/api/digest/preview?date=`, `/api/backup/list`, `/api/backup/latest`, `/api/security/events`, `/api/security/summary` | Служебное |
| GET | `/api/qr?data=&border=` | SVG QR, только для адресов этого сайта |

Контракты этих ручек описываются в начале фазы 8 по коду бэкенда.
