# 05 · Работа с Figma через MCP

Figma — источник правды для визуала, токенов, текстов и состояний. Сверка с макетом — не финальный этап, а часть **каждой** задачи.

## 1. Подключение

| Агент | Команда |
|---|---|
| Codex | `codex mcp add figma --url https://mcp.figma.com/mcp`, затем авторизация в Figma и проверка `codex mcp list` |
| Claude Code | `claude mcp add --transport http figma https://mcp.figma.com/mcp` |

Используется удалённый сервер Figma. Нужен доступ аккаунта к файлу `QDbhShERrxdg5nXHbrr27s`.

В облачных задачах (ночью, компьютер выключен) MCP недоступен. Агент работает по кэшу `design/figma/` (§8).

**Только чтение.** Агенты ничего не создают и не меняют в файле. Исключение — прямая просьба Максима.

## 2. Инструменты и когда их звать

| Инструмент | Зачем |
|---|---|
| `get_design_context` | Основной: справочный код, скриншот, ассеты, привязанные переменные узла. Всегда **со скриншотом** |
| `get_variable_defs` | Какие переменные (с CSS-именами) привязаны к узлу. Сверка токенов |
| `get_screenshot` | Эталон для визуальной сверки, если `get_design_context` не вернул скриншот или нужен крупнее (`maxDimension`) |
| `get_metadata` | Структура узла и ID детей, если ответ `get_design_context` помечен sparse |
| `use_figma` | **Только** для экспорта токенов скриптом `scripts/figma-export-tokens.js`. Код только читающий |

## 4. Цикл «макет → код → сверка» (для каждой задачи)

1. **Собери узлы.** Возьми ID из задачи в [09-roadmap.md](09-roadmap.md) или из таблиц выше. Для экрана нужны все фреймы ширин 390 / 768 / 1024 / 1440, которые есть в секции.
2. **`get_design_context` со скриншотом** на каждый узел. Скриншот — визуальная цель, а **не** ассет для кода.
   - Ответ помечен sparse → по скриншоту и `get_metadata` найди видимые дочерние узлы и запроси их одним параллельным пакетом.
   - Реализуй только по полным (high-fidelity) ответам.
3. **`get_variable_defs`** на узел и ключевые дочерние узлы. Это список CSS-переменных, которые ты имеешь право использовать в этом месте.
4. **Адаптируй, а не копируй.** Справочный код MCP — это неинтерактивный прототип.
   - Абсолютное позиционирование переводи в flex или grid, если дизайн не требует фиксированной позиции.
   - Используй существующие компоненты `src/ui/`, токены, шрифты, иконки. Не плоди дубли.
   - Интерактивные части делай интерактивными: кнопки — `<button>`, ссылки — `<a>`, поле — `<input>` с `<label>`.
5. **Ассеты.**
   - Каждый статичный ассет из ответа MCP скачай **локально в репозиторий** (`src/assets/...`) и используй ровно в том месте, где он стоит в макете.
   - Не перерисовывать, не редактировать, не вытаскивать пути из SVG, не заменять похожим.
   - У SVG сохраняй корневые `width` и `height`.
   - Временных ссылок `figma.com/api/mcp/asset/...` в коде быть не должно — их проверяет ревью.
   - Изображения, которые приходят из данных (API), остаются динамическими.
6. **Тексты.** Дословно из макета в `src/content/`. Номера заказов в макете («112», «108 · 110…») — пример данных, а не контент.
7. **Состояния.** Все варианты компонента из Figma, а также hover, pressed, focus-visible и disabled, даже если на экране виден один.
8. **Сверка** (§5). Расхождения исправить; то, что исправить нельзя, описать в PR.

## 5. Критерии совпадения с макетом

Playwright-скриншот снимается на ширине фрейма Figma (390, 768, 1024, 1440), на тех же данных (номер 112, тот же список очереди), со шрифтами, которые уже загрузились (`document.fonts.ready`).

| Что | Критерий |
|---|---|
| Цвета | Точно токены, привязанные в Figma. Сверять значения переменных, а не пиксели скриншота |
| Типографика | Тот же стиль текста (гарнитура, начертание, кегль, интерлиньяж) |
| Геометрия | Положение и размеры блоков ±2 px; отступы — из шкалы `--space-*`, как в Figma |
| Радиусы, обводки | Точно как в Figma |
| Ассеты | Все на месте, нужного размера и пропорций, без искажений |
| Тексты | Дословно, включая неразрывные пробелы и символы `₽`, `№`, `·` |
| Переносы строк | Могут отличаться из-за рендера шрифтов. Допустимо, если не ломает раскладку и не меняет высоту блока более чем на одну строку |

Пары скриншотов «Figma / реализация» прикладываются к PR. После приёмки Claude Code фиксирует наш скриншот эталоном для регрессии (`toHaveScreenshot`).

## 6. Если макет и что-то ещё не сходятся

| Ситуация | Действие |
|---|---|
| Макет требует данных, которых нет в API (бот Telegram, промокод, игра) | Элемент скрыть фиче-флагом, вопрос — в [10-decisions.md](10-decisions.md) |
| Для состояния или ширины нет фрейма | Не придумывать. Вопрос; до ответа — ближайший фрейм той же секции, в PR пометить «нет макета» |
| Узел не привязан к переменной (сырое значение) | Вопрос (Q-13). Не подбирать «похожий» токен |
| Описание компонента противоречит значению токена | Правда в значении токена ([04-design-system.md](04-design-system.md) §12) |
| Текста нет в Figma (уведомления, ошибки сети) | Текст из legacy с пометкой `source: legacy` и вопрос |

## 7. Позже: Code Connect

Когда компоненты фазы 1 стабилизируются, можно связать узлы Figma с компонентами `src/ui/` через Figma Code Connect — тогда MCP будет сразу предлагать наши компоненты. Это отдельное решение (ADR) и, возможно, новая dev-зависимость, поэтому в бэклоге.

## 8. Кэш Figma и бюджет запросов

Облачный агент ночью работает без MCP — по кэшу `design/figma/`. Кэш заранее снимает Claude Code ([12-night-mode.md](12-night-mode.md) §4).

Кэш полезен и днём. Лимит MCP на чтение — 200 вызовов в день на тарифах Pro и Organization с местом Full или Dev (Q-23), и его делят все агенты под одним аккаунтом. Поэтому:
- сначала смотреть в кэш;
- MCP вызывать только для узлов, которых в кэше нет или которые изменились в Figma.
