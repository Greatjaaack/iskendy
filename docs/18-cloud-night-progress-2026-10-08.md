## W2-4 · сигналы готовности

- Единый владелец переходов читает свежую запись и cache, сначала сохраняет переход,
  затем выдаёт сигнал. StrictMode/repeated ticks не повторяют звук/вибрацию/уведомление.
- Возврат ошибочно выданного заказа заново вызывает сигнал. Сброс/новый день/отсутствие
  свежего заказа не создают ложных уведомлений.
- Звук/вибрация/Notification деградируют независимо; подписи и паттерны из legacy.
- На личном экране сохранён live-status; на очереди добавлено только невидимое
  объявление готовности. Новая визуальная композиция не создавалась.
- Напоминание об оценке намеренно ещё не расходует promptedAt: экрана оценки пока нет,
  поэтому нельзя звать гостя в незавершённый сценарий.
- Facts CSS уже соответствует финальному указанию Figma; изменять его не потребовалось.
  Добавлены будущие E2E для всех шести вариантов с 272px шириной, длинным текстом,
  одинаковой высотой двух карточек и отсутствием overflow.

## W2-6 · разрешение уведомлений

- Разблокировка аудио остаётся в обработчике действия до сетевого await. Permission
  спрашивается только после успешной подписки/сохранения; invalid/taken/429 не спрашивают.
- Уход с Entry отменяет текущий запрос и запрещает позднему ответу менять маршрут,
  запись или вызывать permission. Повторный submit во время запроса дедуплицируется.
- Denied/unsupported/rejected Notification API не мешают отслеживанию заказа.
  Ожидание регистрации и ready у worker ограничено целиком; выдача permission не ждёт его.
- Mock-preview перехватывает только платформенные адаптеры в test-only модуле:
  нет настоящего permission UI и замены корневого MSW worker. Production эту часть не включает.
- 325 unit/component-тестов прошли; static/build/size проходят. Browser E2E только добавлены,
  не выполнены в ограниченной облачной среде. Нужны реальные устройства для user activation.

## W2-7 · воронка и технические события

- Сохранены имена board_open/sub_try/sub_fail/sub_ok/sub_pending/ready_seen и целей.
  board_open/success/ready_seen дедуплицируются в рамках реального session id;
  sub_try/sub_fail остаются на каждую попытку.
- Метрика получает только белый список экранов/имён целей, без номера/ключей/форм.
  Реальный скрипт Метрики отключён только в mock-режиме; production сохраняет свой счётчик.
- Готовность на скрытой вкладке не пишет ready_seen до её видимого подтверждения.
  Старая запись без свежего board также не считается новым просмотром готовности.
- Permission-цели описывают только новое решение, а не уже выданное разрешение.
- Client-event reporting подключён к JS-ошибкам/длинному восстановлению связи;
  lease блокирует общую с claim корзину на всём протяжении подписки и освобождается
