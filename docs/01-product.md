# 01 · Продукт

## 1. Искенди и задача сервиса

«Искенди» — дюрюмная: турецкий стрит-фуд, главный продукт — дюрюм. Бренд позиционируется как современная уличная гастрономия, а не шаурма. Это правило действует и для текстов интерфейса.

Сервис «Где мой заказ» снимает толпу у окна выдачи в час пик:
- гость не стоит у стойки, а следит за заказом с телефона;
- когда заказ готов, телефон сам его зовёт;
- после выдачи гость оценивает заказ.

Негатив уходит управляющему в рабочий чат и наружу не попадает. Довольных гостей мы приглашаем оставить отзыв на Яндекс Картах.

Как устроена система (бэкенд уже работает):
1. Касса пробивает заказ.
2. Через аналитику заказ автоматически попадает в базу табло со статусом «готовится».
3. Кассир на планшете (`/staff`) переводит заказ в «готово», затем в «выдано».
4. Гость видит статус на телефоне (`/board`) и на ТВ в зале (`/tv`).
5. Отзывы и статистика уходят в `/stats` и в Telegram владельцам.

## 2. Пользователи и устройства

| Кто | Где | Устройство | Что важно |
|---|---|---|---|
| Гость | `/`, `/board` | Свой телефон: iPhone и Android, часто встроенный браузер Telegram или приложения-сканера QR | Первая загрузка по мобильной сети, понятность без инструкций, одна рука, плохая связь в зале |

| Владельцы | `/stats` | Ноутбук или телефон | Аналитика, отзывы |

## 6. Жизненный цикл заказа глазами гостя

Логика повторяет legacy (`legacy/index.html`: функции `subSubmit`, `subTo`, `claimEnsure`, `fbWatch`, `fbAskServed`, `myPendingLimit`). Реализуется чистыми функциями в `src/domain/order/`.

### 6.1 Запись «мой заказ» (`localStorage['iskendi_my_order']`)

JSON с полями, которые пишет legacy. **Неизвестные поля сохранять как есть**, чтобы откат на legacy посреди заказа не ломал гостю экран.

| Поле | Тип | Смысл |
|---|---|---|
| `n` | number | Номер заказа |
| `d` | string `YYYY-MM-DD` | День табло на момент подписки (`date` из `/api/status`) |
| `seen` | bool | Номер хотя бы раз был на табло |
| `subAt` | ms | Когда подписался |
| `claim` | string | `claimToken`, может быть пустым, если подписка прошла без сети |
| `servedAt` | ms, 0 — нет | Когда фронт заметил выдачу |
| `promptedAt` | ms | Когда позвали оценить |
| `rated` | bool | Отзыв уже есть |
| `done` | bool | Сценарий завершён |
| `gone` | bool | Заказ снят кассиром |
| `lastStatus` | string | Последний известный статус (для однократных сигналов) |
| `fb` | `{id, token, rating, branch, detailSent}` | Отзыв и ключ его правки |

### 6.2 Состояния (вычисляются, не хранятся)

| Состояние | Условие | Экран |
|---|---|---|
| `none` | Записи нет | `Entry` |
| `pending` | `!seen` и номера нет на табло, ожидание короче порога | `Order` с текстом «Ждём кухню». Отдельного макета нет (Q-18) |
| `notFound` | `!seen` и ожидание длиннее порога: 1 мин, а в начале дня (`servedCount == 0`) — 4 мин. Либо `gone` | `Entry` в состоянии «номер не найден» (`68:1160` / `82:794`) с кнопкой «Найти на табло». Запись сохраняется: если номер появится, экран оживёт |
| `preparing` | Номер на табло, статус `open` или `preparing` | `Order` · preparing |
| `ready` | Номер на табло, статус `ready` | `Order` · ready. Однократный сигнал: звук, вибрация, системное уведомление |
| `checking` | `seen`, номера на табло нет, `servedAt == 0` | Последнее известное состояние. Фон: `GET /api/feedback/check` не чаще раза в 20 с |
| `issued` | `servedAt > 0` | `Order` · issued с блоком оценки |
| `rated` | `rated` или `fb.id` | `Order` · issued, состояние «спасибо» |

### 6.3 Переходы по ответу `GET /api/feedback/check` (из `checking`)

| Ответ | Действие |
|---|---|
| `ok: true` | `servedAt = now`, `gone = false` → `issued` |
| `reason: "already"` | `rated = true` → `rated` |
| `reason: "not_found"` | `gone = true` → `notFound` (кассир снял заказ — путь тот же, что у опечатки) |
| `reason: "not_served"` | Ничего не менять, ждать |

### 6.4 Особые события

- **Откат выдачи.** Номер снова появился на табло при `servedAt > 0`. Сбросить `servedAt`, `promptedAt`, `gone` и вернуться в `ready`. Касса откатила ошибочную выдачу, и телефон должен позвать гостя снова.
- **Новый день.** `date` из `/api/status` не равна `d`. Удалить запись, показать `Entry`.
- **«Это не мой номер»** (экран «Готово») и **«Отследить другой заказ»** (экран «Выдан»). Удалить запись, показать `Entry`, фокус в поле номера.

### 6.5 Задержка оценки

Задержка `promptDelaySec` (по умолчанию 180 с, приходит из `/api/feedback/config`) отсчитывается от `servedAt`. По её истечении — однократный «позыв» оценить: шаг `rate_shown`, звук, вибрация, системное уведомление.

Блок оценки по Figma виден на экране «Выдан» сразу (M5, D5). Это отличие от legacy, где карточка оценки появлялась только после паузы (Q-19).

## 7. Подписка: ввод номера (`Entry`)

1. **Проверка ввода.** Целое число от 1 до 100000 (ограничение бэкенда). Поле `inputmode="numeric"`, тексты подсказок и ошибок — из `Web/Input kind=order-number`. Каждая попытка пишет шаг `sub_try`.
2. **Номер уже на табло** — подписаться (п. 4).
3. **Номера на табло нет** — `GET /api/feedback/check?number=`:

   | Ответ | Действие |
   |---|---|
   | `ok: true` (уже выдан) | Запись `{seen: true, servedAt: now, promptedAt: now, rated: false, done: false, lastStatus: "served"}` без claim (claim — перед оценкой). Цель Метрики `sub_served`, шаг `sub_ok` → `Order` · issued |
   | `not_served` | Подписаться (п. 4) |
   | `already` | Запись с `rated: true, done: true, lastStatus: "served"`. Цель `sub_served`, шаг `sub_ok` → `Order` · rated |
   | `not_found` | Подписаться авансом (`seen: false`): касса ещё не довезла номер. Шаги `sub_ok` и `sub_pending` |
   | Другое | Показать `message` с сервера, цель `sub_fail`, шаг `sub_fail` |
   | Нет сети | Ошибка поля «нет связи», подписки нет |

4. **Подписка** — `POST /api/guest/claim {number, guest}`:

   | Ответ | Действие |
   |---|---|
   | `ok` | Сохранить `claimToken` в `claim` |
   | `ok:false` (`taken`, `too_many`) | Показать `message`, шаг `sub_fail`, подписки нет |
   | 429 | Сообщение о перегрузке, подписки нет, автоповтора нет |
   | Таймаут или сеть | Подписаться без ключа (`claim: ""`). Ключ добрать перед оценкой — один повтор с тем же `guest`, ADR-005 |

5. **После подписки:**
   - вибрация 30 мс;
   - цель `sub_ok`, шаг `sub_ok`;
   - разблокировать звук: в обработчике этого же нажатия;
   - открыть `Order`;
   - запросить разрешение на уведомления — именно здесь, как продолжение нажатия; цели `notif_granted` / `notif_denied`.

Тап по чужому номеру на табло **ничего не открывает**: подписка только по номеру со своего чека. Это защита приватности — гость не должен разглядывать чужие заказы.

## 8. Сигнал «Готово»

Срабатывает один раз на переход в `ready` (сравнение с `lastStatus`):
- короткий звук через WebAudio (звук разблокирован жестом при подписке);
- вибрация;
- системное уведомление через `ServiceWorkerRegistration.showNotification` (`tag: "iskendy-order"`, `renotify: true`); тап по нему ведёт на `/board?my=1`;
- цель `order_ready`, шаг `ready_seen`, если страница видима;
- объявление для скринридера через `aria-live="polite"`.

Тексты уведомлений в Figma отсутствуют, берутся из legacy и помечаются в `src/content/` как `source: legacy`.

## 9. Оценка (`Rating`)

Мобайл — модальное окно (M-R*), планшет и десктоп — диалог (D-R*). Компоненты: `Web/EmotionSlider`, `Web/EmotionCharacter`, `Web/ReasonChip`, `Web/Input kind=comment`, `Web/Consent`.

### Эмоции

| Значение (`rating`) | Эмоция | Персонаж |
|---|---|---|
| 1 | Злость | Бурк |
| 2 | Грусть | Кап |
| 3 | Так себе | Мэх |
| 4 | Хорошо | Тёп |
| 5 | Восторг | Блик |

Подписи краёв шкалы: «ВСЁ ПЛОХО» и «ВСЁ СУПЕР».

### Шаги

1. **R1 · Эмоция.** Слайдер с 5 остановками, «Дальше» → `POST /api/feedback {number, rating, claim_token}`. Если `claim` пуст, сначала один раз `claimEnsure`.
   - `ok` → сохранить `fb = {id, token, rating, branch}`, цель `rate`, шаг `rated`.
   - `not_claimed` → текст «оценить можно с того телефона, на котором вы следили».
   - `already` → перейти в «спасибо».
2. **R2 · Причины.** Множественный выбор, «Дальше» или «Пропустить». Набор причин и заголовок зависят от ветки `branch` из ответа сервера. Порог «негатива» в коде не дублировать.

   | Ветка | Заголовок (по Figma) | Причины |
   |---|---|---|
   | negative | «Что вас разозлило?» | Долгое ожидание · Остыло · Не то в заказе · Невкусно · Грубое общение · Грязно · Дорого · Другое |
   | positive | «Что порадовало?» | Вкус · Скорость · Порция · Подача · Персонал · Атмосфера · Цена · Похвалить сотрудника |

   Заголовки для эмоций 2–4 в макетах не нарисованы (Q-21).
3. **R3 · Комментарий** (ветка negative): необязательный текст до 1000 символов. Согласие «Свяжитесь со мной в Telegram» скрыто флагом до ответа на Q-07. Кнопка «Отправить управляющему» → `POST /api/feedback/detail {feedback_id, edit_token, tags, comment, contact}`, цель `feedback_sent`.
4. **R4 · Спасибо.** Варианты «грусть» и «восторг». Ссылка «Оставить отзыв на Картах» берёт `links.yandex` из `/api/feedback/config`, клик пишет шаг `review_click`.
   - Ветка positive: если причины выбраны, перед R4 тоже уходит `detail` (только `tags`).
   - Ссылка на Яндекс Карты по десктопному макету D5 предлагается **всем гостям**, без бонусов и без зависимости от оценки: «таковы правила Яндекса». Legacy показывал её только при 4–5★.
5. **Смена эмоции после отправки** (вернулся с R2 на R1) → `POST /api/feedback/rate`. Пока детали не отправлены и окно правки не истекло; иначе сервер вернёт `locked` или `expired`, показать его `message`.

**Теги.** Бэкенд хранит теги одной строкой через запятую. Значение тега не может содержать запятую и длиннее 40 символов, максимум 12 тегов. Значения — тексты из Figma; соответствие старым тегам для аналитики — Q-08.

## 10. Навигация

По Figma, секция 8, и компонентам `Web/Dock` и `Web/NavSwitch`.

- **Мобайл (< 768, Q-04): `Web/Dock` внизу.** Слева «Табло», справа «Помощь», в центре «мой заказ» — номер с кольцом прогресса цвета статуса:

  | Статус | Кольцо |
  |---|---|
  | preparing | 50 %, жёлтое |
  | ready | 75 %, олива |
  | issued | 100 %, розовое |

  Док и основные кнопки чёрные.
- **Планшет и десктоп (≥ 768): `Web/NavSwitch` в шапке** — Заказ · Табло · Помощь, вариант `hasOrder`.
- **Центральная кнопка «мой заказ»:**
  - Заказа нет — с любого экрана ведёт на ввод номера с фокусом в поле. Если уже там — прокрутка вверх и фокус.
  - Заказ есть — открывает заказ. Если уже на нём — прокрутка вверх.
  - Статус «готово» — открывает заказ на блоке «Как забрать», точка «Новое» гаснет.
  - Выдан, но не оценён — заказ с блоком оценки. Выдан и оценён — заказ со «спасибо» и «Отследить другой заказ».
- **Смена статуса, пока гость на «Табло» или «Помощи»:** кольцо меняет цвет, появляется точка «Новое», скринридер объявляет смену.
- **Кнопки навигации никогда не блокируются**, даже без связи.
- **`Web/ReturnBar`** — полоса возврата к своему заказу под шапкой на «Табло», пока заказ не выдан. Вся полоса — ссылка. Цвет совпадает со статусом.

## 11. Табло, Помощь, Нет связи

- **Табло** (`view=queue`). Две колонки «Готовим» (`open` + `preparing`) и «Готово», номера по возрастанию — порядок даёт сервер. Свой номер выделен: `Web/QueueChip mine=true`, кольцо и подпись «ваш» — не только цветом. Подпись «Обновляется автоматически». Показ очереди на телефоне — Q-14.
- **Помощь** (`view=help`). Связь с управляющим, адрес со ссылкой на Яндекс Карты, часы работы, соцсети. Данные — Q-06 и Q-09.
- **Нет связи.** Экраны `05` и `D8`. Когда показывать и показывать ли последние данные — Q-01.

## 13. Аналитика (непрерывность с legacy)

### Яндекс.Метрика

- Счётчик `110894396`.
- Работает только на `/` и `/board`. На `/tv`, `/staff`, `/stats` — не инициализируется.
- Просмотры при смене экрана отправляются вручную (`hit`), без дублей подряд.
- Цели, имена не менять:

  | Цель | Когда |
  |---|---|
  | `sub_ok` | Подписка на заказ |
  | `sub_fail` | Неудачная попытка подписки |
  | `sub_served` | Подписка на уже выданный заказ |
  | `order_ready` | Заказ стал готов |
  | `rate` | Поставлена оценка |
  | `feedback_sent` | Отправлены детали отзыва |
  | `notif_granted`, `notif_denied` | Ответ на запрос уведомлений |

### Воронка `/api/guest/event`

- Шаги: `board_open` → `sub_try` → `sub_fail` / `sub_ok` (+ `sub_pending`) → `ready_seen` → `rate_shown` → `rated` → `review_click`.
- Каждый шаг — один раз за визит, кроме `sub_try` и `sub_fail`: их пишем при каждой попытке.
- В запросе: `session` (`iskendy_visit`), `guest` (`iskendy_guest`), `number` — если подписан.
- Отправка с `keepalive: true`, ошибки молча игнорируются.
