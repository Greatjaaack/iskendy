# Feedback check: устойчивый интервал · 2026-10-09

## Исправление

Повторная проверка возможности отзыва для одного номера ждёт 20 секунд
между началами запросов. Date.now() измерял этот интервал по системным часам:
перевод часов вперёд на час позволял запросу уйти немедленно, назад — добавлял
час ожидания. Обе ошибки воспроизведены тестами на прежнем коде:
2 FAIL / 5 PASS, evidence/regression-before.log.

Теперь частный таймер createFeedbackCheckGate использует performance.now().
Перевод системных часов не изменяет интервал. Это только elapsed clock внутри
экземпляра gate: даты, формат storage и API не меняются. Инъекция часов для
тестов сохранена. Частота 20 секунд, abort и свежий ответ каждого запроса прежние.

Добавлены регрессии для перевода часов на час в обе стороны и для медленного
первого запроса: второй запрос того же номера не перекрывает первый даже
после истечения интервала, а другой номер продолжает независимо. Ни claim,
ни повтор POST, ни автоматический повтор 429 не добавлены.
