# 12 · Ночной режим: облачный агент при выключенном компьютере

Ночью компьютер Максима выключен. Код пишет **облачный агент**. По умолчанию это Codex cloud: каждая задача идёт в отдельном контейнере, репозиторий клонируется из GitHub, результат — PR. Утром работу принимает Claude Code.

Правила `AGENTS.md` действуют полностью. Здесь — только то, что ночью работает иначе.

## 1. Суточный цикл

| Когда | Кто | Что |
|---|---|---|
| День / вечер (компьютер включён) | Claude Code | Принимает ночные PR ([`CLAUDE.md`](../CLAUDE.md)), мёржит, снимает кэш Figma для задач следующей ночи (§4), готовит тексты ночных заданий (§6) |
| Вечер | Максим | Запускает облачные задачи — по одной на задачу из очереди (§5). Можно с телефона: из приложения или веб-версии Codex |
| Ночь | Облачный агент | Работает в контейнере без интернета, по кэшу Figma и моку API (MSW). Открывает PR |
| Ночь | GitHub Actions | На каждый PR прогоняет CI и сохраняет отчёт и скриншоты Playwright |
| Утро | Claude Code | Ревью, сверка скриншотов с Figma, мерж или возврат с замечаниями (§8) |

## 2. Чем ночь отличается от дня

| | День | Ночь в облаке |
|---|---|---|
| Figma | Figma MCP вживую | **Только кэш** `design/figma/`, снятый через MCP заранее |
| Интернет | Есть | Во время работы агента **нет**. Зависимости ставит setup-скрипт среды |
| Бэкенд | Локальный Docker | Нет — только MSW и фикстуры `tests/fixtures/` |
| Устройства | Реальные телефоны | Только эмуляция Playwright |
| Зависимости | Новые — через ADR | Не ставятся и не меняются: `package.json` и lockfile не трогаем |
| Вопросы | Можно спросить Максима | Некому. Вариант по умолчанию за флагом или остановка на этой части |

## 3. Облачная среда (настраивается один раз)

Для Codex cloud: настройки Codex → Environments → среда для `iskendy-web`.

| Параметр | Значение |
|---|---|
| Репозиторий | `iskendy-web` на GitHub (Q-22 — без репозитория ночная работа невозможна) |
| Версия Node | Как в `.nvmrc`: в настройках среды или в setup-скрипте |
| Setup-скрипт | См. ниже. Выполняется с интернетом, результат кэшируется |
| Maintenance-скрипт | `npm ci` — на случай, если lockfile изменился после мержей |
| Интернет агента | **Выключен** (так по умолчанию, не включать) |
| Секреты и переменные | **Нет.** Фронту они не нужны |

```bash
# setup-скрипт облачной среды
set -euo pipefail
npm ci
npx playwright install --with-deps chromium webkit
```

**Проверка среды** — первая облачная задача, ещё днём: «Выполни `npm run verify`, ничего не меняй, пришли вывод». Если что-то падает из-за среды (браузеры Playwright, версия Node), среду чинят до первой ночи.

## 4. Кэш Figma (`design/figma/`)

В облаке нет доступа к Figma MCP. Поэтому всё, что агент взял бы из MCP, Claude Code снимает **заранее, через тот же MCP**, и кладёт в репозиторий. Кэш ещё и бережёт дневной лимит MCP.

```
design/figma/
├─ INDEX.md            какие узлы нужны каким задачам, дата снятия
└─ <nodeId>/           например 67-79 (двоеточие заменяется дефисом)
   ├─ meta.json        имя узла, страница, размеры, дата снятия
   ├─ context.tsx      справочный код get_design_context — как есть, без правок
   ├─ variables.json   ответ get_variable_defs
   ├─ screenshot.png   get_screenshot, maxDimension 2048
   └─ assets/          ассеты узла, скачанные по ссылкам из ответа MCP
```

**Правила кэша:**
1. Снимает Claude Code вечером, при включённом компьютере, для задач следующей ночи. Ссылки на ассеты из ответа MCP живут недолго, поэтому файлы скачиваются сразу. Ссылок на `figma.com` в кэше быть не должно.
2. Кэш попадает в `main` отдельным PR `chore/figma-cache-<дата>` **до** запуска ночи.
3. Кэш — копия, источник правды остаётся Figma. Максим поменял макет — говорит об этом, и Claude Code переснимает затронутые узлы.
4. Агент использует кэш так же, как ответы MCP ([05-figma-workflow.md](05-figma-workflow.md) §4):
   - `context.tsx` — прототип, а не готовый код;
   - `variables.json` — список токенов, разрешённых в этом месте;
   - `screenshot.png` — цель сверки;
   - `assets/` — ассеты как есть.
5. Нужного узла в кэше нет — эта часть задачи не делается, в PR пишется «нет кэша для узла X».

**Бюджет запросов.** Дневной лимит MCP на чтение зависит от тарифа и места в Figma (Q-23):

| Тариф и место | Лимит |
|---|---|
| Pro или Organization, место Full или Dev | 200 в день |
| Enterprise | 600 в день |
| Starter, место View или Collab | 6 в месяц |

Сверху — поминутные ограничения. Источник: <https://developers.figma.com/docs/figma-mcp-server/plans-access-and-permissions/>.

Один узел — примерно 3 вызова: контекст, переменные, скриншот. При лимите 200 вечером снимается **не больше ~50 узлов**, остальное — резерв на утреннюю сверку. Утренняя сверка идёт по кэшированным скриншотам; живой вызов MCP — только в спорных местах.

## 5. Очередь и зависимости

Задача запускается ночью, только если **все её зависимости уже в `main`**. Параллельно — не больше 3 задач за ночь, чтобы утренний разбор помещался в утро. Параллельные задачи не должны править одни и те же файлы.

| Задача | Зависит от | Режим |
|---|---|---|
| W0-1 | — | **День.** Ставит весь список пакетов ADR-001 и заводит все npm-скрипты |
| W0-2 | W0-1 | **День, Claude Code**: нужен доступ к основному репозиторию |
| W0-3 | W0-1 | Ночь |
| W0-4 | W0-1, W0-2 | Ночь |
| W0-5 | W0-1 | **День, Claude Code**: нужен Docker с бэкендом |
| W0-6 | W0-3 | Ночь |
| W0-7 | W0-2, W0-4 | Код — ночь; проверка на устройствах — день |
| W0-8 | W0-5 | Ночь |
| W0-9 | W0-1 | Ночь |
| W0-10 | W0-8, W0-9 | Ночь |
| W0-11 | W0-1 | Ночь |
| W1-1, W1-2 | W0-3, W0-6, кэш узлов | **Днём** — первые компоненты, чтобы проверить цепочку «кэш → код → сверка» |
| W1-3…W1-14 | W1-1, W1-2, кэш узлов | Ночь |
| Фазы 2–4 | Компоненты фазы 1, кэш экранов | Ночь. Приёмка — e2e-сценарии из [07-testing.md](07-testing.md) §6 |
| Фаза 5, релизы, интеграция | — | **Только день** |

**Чтобы параллельные PR не конфликтовали:**
- **`package.json` после W0-1 не меняется.** W0-1 сразу ставит все пакеты из ADR-001 и заводит все скрипты из `AGENTS.md` §4. Пока скрипт не реализован, он печатает «ещё не реализовано: W0-x» и завершается успешно. Ночью поставить пакет и так нельзя — нет интернета.
- **Витрина** собирает компоненты сама (`import.meta.glob`), общий реестр руками не правится.
- **Тексты** — по файлу на экран или компонент в `src/content/`, без одного общего файла.
- **Эталонные скриншоты** агент не коммитит. CI на PR генерирует недостающие (`--update-snapshots=missing`) и выкладывает их артефактом. Утверждает и коммитит их Claude Code ([07-testing.md](07-testing.md) §8).

## 6. Ночное задание (шаблон)

Вставляется в облачную задачу как есть, с заменой ID и ветки:

```text
Задача: W0-9 — «Хранилище и домен заказа» (docs/09-roadmap.md).

Ты работаешь в облаке ночью: без интернета, без Figma MCP, без бэкенда.
Владелец спит, спросить некого.

1. Прочитай AGENTS.md, docs/12-night-mode.md и документы, на которые ссылается задача.
2. Ветка feat/w0-9-storage-domain. Один PR, черновик — пока verify не зелёный.
3. Макеты — только кэш design/figma/ (узлы задачи перечислены в design/figma/INDEX.md).
   Узла нет в кэше — эту часть не делай, напиши в PR.
4. Не трогай package.json, lockfile, legacy/, public/sw.js, design/figma/. Не добавляй зависимостей.
5. Открытый вопрос с вариантом по умолчанию — делай вариант за флагом.
   Без варианта — остановись на этой части, остальное доделай, опиши в PR в разделе «Заблокировано».
6. «Готово» — только при зелёном npm run verify, вывод приложи к PR.
   Не зелёный — PR остаётся черновиком с описанием, что падает и почему.
7. PR — по шаблону .github/pull_request_template.md.
```

Для задач с вёрсткой добавляется пункт:

```text
8. Сделай скриншоты Playwright на ширинах фреймов из кэша (390 / 768 / 1024 / 1440),
   сравни с design/figma/<узел>/screenshot.png и опиши в PR все расхождения.
```

## 7. Что агент оставляет к утру

- PR, черновик или готовый, оформленный по шаблону: вывод `verify`, раздел «Заблокировано», если есть.
- Артефакты CI: отчёт Playwright, скриншоты, кандидаты эталонов.
- Никаких изменений вне задачи.

## 8. Утренний разбор (Claude Code)

1. Собрать ночные PR и статусы CI.
2. Ревью каждого PR по [`CLAUDE.md`](../CLAUDE.md) §2. Визуал — скриншоты из артефактов CI против `design/figma/<узел>/screenshot.png`. Живой вызов MCP — только при сомнении.
3. Вердикт. Мерж — по порядку зависимостей. Утверждение эталонов.
4. Вернул задачу — в следующую ночь тот же ID, замечания добавляются в текст задания.
5. Вечером — кэш Figma и задания на следующую ночь.

## 9. Ночью нельзя

- Релизы, теги, интеграция, деплой, основной репозиторий.
- Новые зависимости, правки `package.json` и lockfile.
- Мерж чего-либо. Автомерж в GitHub выключен.
- Включать агенту интернет, добавлять секреты в облачную среду.
- Задачи, которые зависят от ещё не смёрженных задач.
- Фаза 5 и всё, что требует реальных устройств, бэкенда или решения Максима.
- Плагины процесса вроде Superpowers: процесс задают `AGENTS.md` и текст задания.

## 10. Безопасность облака

- Интернет агента выключен: агент не может ни отправить код наружу, ни скачать чужой скрипт.
- Секретов в облачной среде нет. Токены для релизов живут только в секретах GitHub Actions.
- `main` защищён: только PR, зелёный CI, без автомержа. Облачный агент может создавать ветки и PR — больше ничего.
- В кэше Figma нет временных ссылок, ассеты — только свои.
