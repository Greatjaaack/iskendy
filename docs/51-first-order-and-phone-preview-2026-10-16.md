# Первый заказ и тестовый стенд · 16.10.2026

По запросу владельца добавлен отдельный первый экран. До первого добавления показываются заголовок «Где мой заказ?», пояснение, поле номера с подсказкой и «Показать статус». Быстрые действия и сервисы появляются после успешного добавления. Черновик не пропадает при добавлении заказа из другой вкладки.

## Тестовые серверы

- 5173 — предыдущий просмотр, сохранён.
- 5176 — отдельный локальный стенд, `/dev/scenarios.html`.
- 5177 — стенд для Wi-Fi телефона, слушает `0.0.0.0`.

Адрес ноутбука при создании QR: `192.168.1.67`. Телефон должен быть в той же сети; адрес может измениться при переподключении. Ноутбук и процесс должны оставаться включёнными.

QR-файлы сгенерированы локально: `dev/phone-scenarios-qr.png` — выбор сценария; `dev/phone-orders-qr.png` — пять тестовых заказов (`orders5`); `dev/phone-entry-qr.png` — ввод первого номера (`entry`). На стенде есть выбор всех пресетов. Каждый явный запуск пресета пересоздаёт только тестовые записи на этом origin; обычная перезагрузка сохраняет результат.

Набор orders5: 112 готовим, 102 готово, 997/998/996 выданы. Их можно оценить любой эмоцией 1–5. Ответы демонстрационные, с формой из сохранённых backend fixtures; идентификатор заказа и оценка согласованы с явным вводом. Интерактивный режим включается только выбранным mock-пресетом. Production не содержит этот код.

В HTTP по LAN сервис-воркеры недоступны: предусмотрен локальный перехват только `/api/` с теми же фикстурами, задержками и AbortSignal. Неизвестные API-запросы не проксируются в настоящий ресторан. При localhost/HTTPS остаётся прежний MSW. Уведомления в mock демонстрируются, реальные системные разрешения не запрашиваются.

Ограничения: отправка вложений и сообщения управляющему по-прежнему ждёт backend API (см. документ 48 / Q-31). В интерфейсе нет выдуманного успеха. Ссылки положительного отзыва — тестовые.

## Правки после физического iPhone

Владелец прислал IMG_4565–4574 и уточнил поведение. После этих снимков:

- Индикатор этапов занимает всю ширину панели; верхний и боковые отступы одинаковые. Для готового и выданного заказа убрана неподходящая подсказка о предстоящем приготовлении.
- Touch-кнопки переключения возвращаются в исходный цвет после отпускания. Hover ограничен точным указателем. Изображения иконок меню не перехватывают касания и выделение.
- Внизу основных экранов учтён safe-area, мобильные промежутки уменьшены. Короткие экраны и увеличенный текст сохраняют естественную прокрутку; содержимое в конце страницы можно поднять целиком над меню.
- Экран эмоций уменьшает портрет под доступную высоту. Ползунок и его подписи видны целиком до панели действий. Из React удалена запись конечного положения в каждом рендере, конфликтовавшая с GSAP. Положение, заливка шкалы и фон эмоции меняются за 240 мс, с прерыванием из текущего состояния; reduced motion переключает сразу.
- Причины компактнее при открытых панелях браузера; сохранены цели касания 44 px и место для теней чипсов. Полоса прокрутки скрыта, сама прокрутка остаётся доступной, когда необходима.
- При фокусе на мобильном input/textarea панель кнопок отзыва и отправка сообщения скрываются. На остальных шагах прокручиваемая область отделена скруглённой панелью действий с тенью. Сообщение управляющему имеет кнопку в потоке после анонимной подсказки, с отступами.

Дополнительные проверки: `tests/e2e/phone-layout.spec.ts`, 430×730 CSS px (панели браузера открыты), уменьшение visualViewport до 410 px, касания iPhone/Android, промежуточные кадры GSAP, причины без прокрутки. Это эмуляция браузеров, не повторный физический прогон на телефоне владельца. Новый QR для повторного прогона ведёт напрямую к `entry` и очищает тестовые заказы перед вводом первого номера.

Финальный прогон после мобильных правок: `npm run verify` успешно — 749 unit, 562 E2E, 31 условный платформенный пропуск. Типы, lint, токены, сборка и размер прошли. Дополнительно форматирование и `git diff --check` прошли. Телефонный адрес на порту 5177 вернул HTTP 200; сервер оставлен работающим. QR заново сгенерирован локально на точный адрес `http://192.168.1.67:5177/dev/scenario.html?preset=entry`.

### Удержание нижнего меню (IMG_4575, IMG_4581)

Розовая линза могла остаться в `held`, если iOS открывал предпросмотр ссылки или пользователь уходил в другую вкладку без обычного pointerup. Добавлен единый сброс при contextmenu, blur, pagehide и скрытии документа; состояние указателя очищается до releasePointerCapture, чтобы lostpointercapture не вызывал повторную обработку. Отменённый жест подавляет последующий ложный click. На touch отключены предпросмотр ссылки и выделение в нижнем меню; обычные ссылки и модифицированные нажатия на компьютере сохранены. Перетаскивание между разделами продолжает работать.

Целевая проверка на iPhone/Android: четыре прерывания удержания, отсутствие навигации после отмены, успешное следующее касание, обычное перетаскивание и pointercancel — 4 теста прошли. Остальные снимки из этой серии не использованы как основание для дополнительных изменений без комментария владельца.

### Быстрые движения шкалы и причина «Другое»

По следующему физическому отзыву владельца шкала переделана с трёх частей (неподвижный круг, масштабируемый прямоугольник, движущаяся головка) на одну заливку-капсулу. Левый край закреплён, ширина равна позиции ползунка плюс его диаметр. Ширина и цвет управляются одним GSAP tween, поэтому нет швов между частями и конфликта отдельных цветовых/геометрических tween. Прерывание начинается с текущих значений; reduced motion использует прежние статичные SVG.

«Другое» открывает существующий Sheet поверх окна оценки с немедленным фокусом в textarea. «ОК» сохраняет текст и выбирает причину; закрытие без подтверждения не меняет черновик. Сохранённый текст можно открыть повторно. Повторное нажатие выбранного чипса снимает причину. Новый API не добавлен, перенос текста в необязательный комментарий сохранён. В Sheet добавлен слой nested, а focusField поддерживает textarea.
