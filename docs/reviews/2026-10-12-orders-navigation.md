## 2. Корень проблемы

Одна задача гостя — «следить за своими заказами» — разложена на **три уровня одной вкладки**: список (`view=orders`), добавление («Где мой заказ?», `/`) и деталь (`order=…&day=…`). Отсюда:

- стрелка «назад» внутри вкладки и дублирование списка на странице добавления (N1, N3);
- вкладка не помнит, на каком уровне был гость (N4);
- для одного заказа появляются промежуточные экраны, а для перехода между заказами нужен пейджер (N2, N6);
- о готовности другого заказа приходится сообщать отдельной плашкой поверх детали (N5).

## 3. Как это решают другие (проверено 12.10.2026)

| Продукт | Паттерн | Что берём |
|---|---|---|
| Табло аэропорта и Flighty | Одна строка на рейс, главное — над сгибом, подробности раскрываются по запросу, статус цветом и словом ([разбор дизайна Flighty](https://blakecrosley.com/fr/guides/design/flighty), [Behind the Design: Flighty](https://cur.at/VcCahLU?m=web)) | Компактная строка на заказ + раскрытие одного |
| Uber Eats | Один баннер активного заказа на главной; если заказов несколько — выбрать, какой отслеживать ([справка Uber](https://help.uber.com/h/4148ea8b-c9d8-409d-b7bf-b2fcb019a498)) | Адаптивность: при одном заказе — сразу деталь |
| Parcel | Список — это главный экран; добавление — одно поле по «+», без отдельной страницы; история видна без лишнего тапа ([Macworld](https://www.macworld.com/article/210215/parcel.html), [обзор](https://syntopikon.substack.com/p/parcel-the-best-package-tracker-on)) | Добавление внутри того же экрана |

Общий вывод: **экран подстраивается под число объектов** — 0 → форма ввода, 1 → сразу деталь, 2+ → список с раскрытием, а добавление происходит без перехода на другую страницу.

## 4. Варианты

### A. Одна адаптивная вкладка «Мои заказы» (рекомендую)

Одна страница, без вложенных уровней, без «назад» и без пейджера.

| Заказов | Что на экране (мобайл) |
|---|---|
| 0 | Заголовок «Где мой заказ?», поле номера, кнопка. Мини-табло и вкладки «Табло» нет — очередь только после подписки (Q-14, 12.10) |
| 1 | Заголовок «Мои заказы», **сразу полный билет**, «Как забрать» (при «Готово»), «＋ Ещё заказ», плитки |
| 2–5 | Заголовок «Мои заказы». Открытым показан один билет (по умолчанию самый срочный: Готово → Готовим → Ждём кухню → Выдан без оценки). Остальные — компактные строки цвета статуса: «№ 108 · Готовим». Тап по строке раскрывает её билет и сворачивает прежний (аккордеон, без перехода) |

- **«＋ Ещё заказ»** раскрывает поле номера прямо на месте (как «+» в Parcel), без отдельной страницы. После подписки новый билет раскрывается.
- **Готовность другого заказа**: строка этого заказа перекрашивается в оливку со словом «Готово» и значком, плюс одно всплывающее уведомление (тост) поверх контента, а не в потоке (см. §5). Порядок строк **на лету не меняется**, чтобы ничего не уезжало из-под пальца; сортировка — только при открытии экрана.
- **Вкладка всегда приводит в одно место**, позиция прокрутки сохраняется (N4 исчезает сам собой).
- **Десктоп ≥ 1024**: слева — билеты и строки, справа — табло с чипами (как в утверждённых `557:12620` и `557:13950`).
- **Удаление (N8)**: у строки и билета — «Убрать из моих заказов» (в меню «⋯» или свайпом). Под ним текст «Номер освободится только завтра», потому что квоту бэкенд не возвращает.

Число касаний на стенде:

| Задача | Сейчас | Вариант A |
|---|---|---|
| Первый заказ | поле + 3 цифры + кнопка | то же |
| Второй заказ | «‹»/вкладка → «Отследить ещё» → новая страница → 3 цифры → кнопка → деталь второго (≈ 4 + цифры) | «＋ Ещё заказ» → 3 цифры → кнопка (2 + цифры) |
| Посмотреть первый, будучи на втором | «‹» → список → тап по строке, или стрелка пейджера (1–2) | тап по строке (1), оба видны сразу |
| Табло → обратно к заказу | вкладка → список → тап (2–3) | вкладка (1) |

### B. Карусель билетов со свайпом (как карты в Wallet)

Пролистывание билетов свайпом, внизу точки-индикаторы.
- Плюсы: красиво, один билет на экране.
- Минусы: статусы других заказов скрыты, свайп неочевиден одной рукой, на десктопе неудобна. При готовности другого заказа всё равно нужен сигнал. **Не рекомендую.**

### C. Переключатель номеров сверху (как выбор заказа в Uber)

Над билетом ряд чипов «108 · 102 ●», точка — цвет статуса, выбранный чип тёмный.
- Плюсы: компактно, нет пейджера, видны все номера.
- Минусы: словом статус не виден (только точкой), а при 5 заказах ряд тесный.
- Годится как **десктопная** подача варианта A или как запасной вариант, если аккордеон не понравится.

## 5. Отдельные решения

1. **Плашка «Заказ готов» (N5).** Убрать из потока страницы. Вместо неё:
   - тост поверх контента у верхнего края, 6 с, с кнопкой «Открыть», `aria-live="polite"`; места не занимает, вёрстка не прыгает;
   - строка заказа в списке становится оливковой;
   - системное уведомление — как сейчас.
   - Повторно тост не показывается, пока статус не изменится.
2. **Пейджер (N2, N6).** В варианте A он не нужен. Если останется: при одном заказе скрыт; активная кнопка — иконка ink на круге sand; неактивная — без круга, иконка 40 %, `disabled`. Правка в Figma (`556:14056`, `556:14102`).
3. **Свой номер на табло (N7).** Рамка без пояснения недостаточна (правило «статус = слово + значок + цвет»).
   - Предложение: под номером в чипе маленькая плашка «ваш», рамка 3 px. Над табло легенда «▢ ваш заказ».
   - Цвет рамки: розовый (`pink`) — это цвет статуса «Выдан». Без подписи он будет путаться со статусом, с подписью «ваш» допустим. Альтернатива — ink, как сейчас, но толще и с подписью. Оранжевый нельзя: он только для логотипа.
   - Решение за тобой; в Figma можно положить оба варианта рядом.
4. **«‹» (N1).** В варианте A стрелки «назад» во вкладке нет. Браузерная «назад» продолжает работать по истории.

## 6. Что поменять в Figma (следующий этап, через MCP)

Секция 11, все четыре ширины (M390 `556:13565`, T768 `558:45891`, T1024 `558:15824`, D1440 `557:11765`):

- **Новые кадры** «Мои заказы · 0 / 1 / 2 / 5»: 0 — бывший A0 с плиткой мини-табло; 1 — бывший D1 без пейджера и «назад»; 2 и 5 — аккордеон, первый открыт.
- **Кадр «＋ Ещё заказ»**: поле раскрыто внутри экрана; варианты ошибок E1 (не найден), E2 (нет связи), E3 (лимит 5) — в строке поля.
- **Компонент «Тост готовности»** (вместо плашки «Заказ № … готов»).
- **Компонент «Строка заказа»** с состояниями: Готовим, Готово, Ждём кухню, Номер не найден, Выдан, Оценено, плюс действие «Убрать».
- **QueueChip `mine`**: плашка «ваш», легенда над табло; два варианта цвета рамки.
- **Убрать или пометить устаревшими**: L1–L3 (список как отдельный уровень), A0–A2 (отдельная страница добавления), пейджер в D1–D3, «Отследить ещё/другой заказ» как переход.

## 9. Подача «как Wallet» для 2–5 заказов

Wallet показывает стопку карт: у каждой видна верхняя полоса с главным (название, баланс, статус), выбранная карта раскрыта целиком, тап по полосе выдвигает её карту.

Для «Искенди» это ложится на вариант A без новых данных и зависимостей:
- **Полоса заказа** ≈ 64 px: слева «№ 108» (Rubik), справа слово статуса со значком; фон — цвет статуса (жёлтый «Готовим», олива «Готово», розовый «Выдан», нейтральный «Ждём кухню» / «Не найден»), текст какао. Полосы ложатся друг на друга с нахлёстом, как в Wallet.
- **Открытая карточка** — полный билет (номер, акцент, факты, шаги, «Как забрать»), сверху стопки. По умолчанию открыт самый срочный заказ, при открытии экрана.
- **Тап по полосе** открывает её карточку, прежняя уходит в стопку. Порядок полос на лету не меняется, при готовности другого заказа его полоса перекрашивается в оливку плюс тост.
- **«⋯» на открытой карточке**: «Убрать из моих заказов».
- **Доступность**: стопка — список кнопок с именами «Заказ 108, Готовим», `aria-expanded`, Enter/Space, порядок фокуса сверху вниз; смена статуса — `aria-live`.
- **Движение**: выдвигание карты — главный эффект Wallet, а ADR-018 разрешает только Loader, Ticker, нажатие кнопок, слайдер и CompactDock. Без нового разрешения смена карт мгновенная (стопка всё равно понятна по форме). Если разрешишь — один эффект «выдвинуть карту» ≈ 250 мс, transform, при `prefers-reduced-motion` — мгновенно.
- **Десктоп ≥ 1024**: стопка в левой колонке, табло справа (как `557:13950`).
- Предел — 5 заказов (лимит бэкенда), поэтому стопка не разрастается.

## 10. Вход по QR

QR на чеке ведёт на `/board` (Максим, 12.10). В варианте A `/board` и `/` открывают одну и ту же вкладку «Мои заказы»: 0 заказов — форма «Где мой заказ?» с мини-табло, есть заказы — стопка. «Табло заказов» — только по `?view=queue` и вкладке дока (UX-22).

## 11. Очередь на телефоне (Q-14)

Очередь показывается только когда у гостя есть хотя бы один заказ: мини-табло под стопкой, вкладка «Табло» в доке, рамка «ваш». Без заказов — одно действие, ввод номера. Блок «Сейчас на кухне» на экране ввода убирается (FIG-07 закрыт этим решением).

**Движение (13.10).** Выдвигание карточки из стопки — FLIP, transform/opacity: полоса переезжает на место открытой карточки и вырастает 250 мс power2.out; содержимое opacity 0→1 150 мс с задержкой 100 мс; прежняя карточка сжимается в полосу, остальные сдвигаются translateY 250 мс; фокус и `aria-expanded` меняются сразу; при `reduce` — мгновенно; повторный тап завершает текущий твин.
