# 07 · Тестирование и качество

Тесты пишет **Codex** вместе с каждой задачей. **Claude Code** проверяет их качество, гоняет полный набор, интеграцию с настоящим бэкендом и устройства, а также утверждает визуальные эталоны.

## 1. Уровни и инструменты

| Уровень | Инструмент | Что проверяем |
|---|---|---|
| Unit | Vitest | Чистая логика: домен заказа и оценки, интервалы опроса, хранилище, API-клиент, схемы |
| Компоненты | Vitest + React Testing Library + `@testing-library/user-event` (jsdom) | Варианты и состояния `src/ui/`, роли, подписи, клавиатура |
| API-моки | MSW | Все ответы: успешные, бизнес-ошибки, 429, 5xx (в том числе не-JSON), таймауты, «дрейф схемы» |
| E2E | Playwright на MSW-сборке | Сценарии гостя целиком на матрице устройств, с управляемыми часами |
| Визуальная регрессия | Playwright `toHaveScreenshot` | Экраны и компоненты на ширинах Figma |
| Интеграция | Playwright против локального бэкенда в Docker + `scripts/progon.py` основного репо | Настоящий контракт API и настоящая раздача статики FastAPI |
| Ручные | Реальные устройства, скринридеры | То, что не эмулируется |

## 2. Команды

| Команда | Что делает |
|---|---|
| `npm test` | Unit-тесты и тесты компонентов (`vitest run`, с покрытием) |
| `npm run test:e2e` | Playwright на MSW-сборке, все проекты-устройства |
| `npm run test:e2e:real` | Playwright против бэкенда по адресу `E2E_BASE_URL`. Нужен `STAFF_PASSWORD` тестового стенда. Запуск только против локального адреса — скрипт отказывается работать с любым другим |
| `npm run verify` | typecheck → lint → check:tokens → test → build → check:size → test:e2e |

## 3. Обязательные unit-тесты

| Модуль | Что покрыть |
|---|---|
| `domain/order/machine` | Все состояния и переходы из [01-product.md](01-product.md) §6. В том числе: `pending` → `notFound` на 1 мин и на 4 мин в начале дня (`servedCount == 0`); откат выдачи; новый день; `gone`; однократность сигналов «Готово» и «оцените» |
| `domain/order/subscribe` | Алгоритм ввода номера ([01-product.md](01-product.md) §7): каждый ответ `check` и `claim`, 429, таймаут и сеть |
| `domain/rating/*` | Выбор набора причин по `branch` сервера; запрет запятых и обрезка тегов до 40 символов; максимум 12 тегов; переходы шагов R1–R4; `rate` после смены эмоции; `locked` и `expired` |
| `polling/interval` | Видима / скрыта; последовательность бэкоффа для `guest` (5 / 10 / 20 / 40 / 60) и `staff` (5 / 10 / 10…); сброс после успеха |
| `polling/connectivity` | Считаются только завершённые запросы; `aborted` не считается; `offlineSince` и порог 30 с |
| `storage/*` | Совместимость с legacy в обе стороны; сохранение неизвестных полей; патч к актуальной версии; приватный режим — исключения не роняют код; формат `iskendy_guest` |
| `api/client` | Таймаут; объединение `signal`; разбор `detail` (строка и массив 422); 429 → `rate_limited`; HTML на 502 → `http`; невалидный JSON; `schema` при дрейфе |
| `api/schemas` | Каждая схема проходит **реальные** фикстуры из `tests/fixtures/` (§5) |
| `platform/clientEvents` | Троттлинг 60 с; блокировка во время подписки; обрезка `detail` до 300; отсутствие токенов в теле |
| `platform/analytics` | Метрика не инициализируется на `/tv`, `/staff`, `/stats`; нет дублей `hit`; в параметрах целей нет токенов и номеров |
| `content/format` | Цена с неразрывным пробелом; `— ₽` для неизвестной цены |

**Покрытие** (порог в `vitest.config`, CI падает при недоборе):
- `src/domain`, `src/api`, `src/polling`, `src/storage` — не меньше 90 % строк и ветвлений;
- остальное — не меньше 70 % строк.

## 4. Тесты компонентов

Для каждого компонента `src/ui/`:
- **Варианты.** Рендер каждого варианта из Figma: тот же набор свойств, что в компоненте Figma.
- **Роли и подписи.**
  - Кнопка — `button`, ссылка — `link`.
  - `Web/Status` — `role="status"`.
  - Слайдер — `role="slider"` с `aria-valuemin`, `aria-valuemax`, `aria-valuenow`, `aria-valuetext`.
  - Поле — связанный `<label>`, подсказка и ошибка через `aria-describedby`.
- **Клавиатура** (`user-event`):
  - Tab-порядок; Enter и Space на кнопках;
  - стрелки, Home и End на слайдере;
  - Esc закрывает диалог, фокус возвращается на кнопку-источник.
- **Состояния disabled и loading** — повторный клик ничего не отправляет.
- **Никаких проверок CSS-значений пикселями** в jsdom: визуал проверяет Playwright.

## 5. Фикстуры и MSW

- **Фикстуры** снимает Claude Code с локального бэкенда (задача W0-5): по файлу на каждый вариант ответа каждого гостевого эндпоинта из [03-api-contract.md](03-api-contract.md):
  - `status` — пустой, с заказами во всех статусах, начало дня;
  - `claim` — ok, `taken`, `too_many`, 429;
  - `check` — ok, `not_found`, `not_served`, `already`;
  - `feedback` — ok positive, ok negative, `not_claimed`, `already`;
  - `rate` — ok, `locked`, `expired`, `wrong_token`;
  - `detail` — ok, `expired`;
  - `config` — со ссылками и без;
  - 422 — пример.

  Фикстуры обезличены: токены заменены на `"<token>"`.
- **MSW-обработчики** строятся на этих фикстурах и переключаются сценариями. В e2e — через тестовый хук, который существует **только** в режиме `mock`. Проверка `check:size` убеждается, что в `dist/` нет кода MSW и тестовых хуков.
- **Тестовые данные** совпадают с макетами: свой номер — `112`; «Готовим» — 108, 110, 111, 112, 113, 114; «Готово» — 102, 104, 107, 109. Так скриншоты сравнимы с Figma.

## 6. E2E-сценарии (обязательные)

Время управляется через `page.clock`: интервалы опроса, пороги 1 и 4 мин, задержка 180 с, троттлинги 20 и 60 с.

Заглушки ставятся через `addInitScript`:
- `ServiceWorkerRegistration.prototype.showNotification` (права на уведомления — через контекст Chromium);
- `navigator.vibrate`;
- `AudioContext`;
- `window.ym`.

Запросы к `mc.yandex.ru` блокируются.

| ID | Сценарий | Ожидание |
|---|---|---|
| E01 | Ввод номера, который есть на табло (preparing) | Экран «Готовим»; ровно один `claim`; запись `iskendi_my_order` с `claim`; цель `sub_ok`; запрос разрешения на уведомления после нажатия |
| E02 | Номера нет на табло, `check` → `not_found` | «Ждём кухню», шаги `sub_ok` и `sub_pending`. Номер появился на табло → «Готовим», `seen: true` |
| E03 | Ожидание без номера дольше порога | Через 1 мин — «номер не найден» с кнопкой «Найти на табло». В начале дня — через 4 мин |
| E04 | Неверный ввод: пусто, 0, буквы, больше 100000 | Ошибка поля по Figma, без запросов `check` и `claim`; шаг `sub_try` |
| E05 | `claim` → `taken` | Текст сервера, подписки нет, шаг `sub_fail` |
| E06 | `claim` → `too_many` | Текст сервера, подписки нет |
| E07 | `claim` → 429 | Текст о перегрузке, **ровно один** запрос, подписки нет |
| E08 | `claim` → таймаут | Подписка без ключа. Перед оценкой — ровно один `claim` (`claimEnsure`) |
| E09 | Подписка на уже выданный заказ (`check` → ok) | Экран «Выдан» с блоком оценки, цель `sub_served`, без `claim` до оценки |
| E10 | Подписка на уже оценённый заказ (`check` → `already`) | «Выдан» в состоянии «спасибо» |
| E11 | preparing → ready | Один сигнал: уведомление, вибрация, звук, текст в `aria-live`. Цель `order_ready`. На следующих опросах повторов нет |
| E12 | ready → номер пропал → `check` → ok | «Выдан». `check` не чаще раза в 20 с |
| E13 | Откат выдачи: номер вернулся на табло | Снова «Готово», сигнал повторяется |
| E14 | Кассир снял заказ (`check` → `not_found` после `seen`) | Путь «номер не найден» |
| E15 | Новый день (`date` сменилась) | Запись удалена, экран ввода |
| E16 | «Это не мой номер» / «Отследить другой заказ» | Запись удалена, экран ввода, фокус в поле |
| E17 | Оценка: злость → причины → комментарий → отправка | `feedback`, затем `detail` с тегами и комментарием; цели `rate` и `feedback_sent`; у полей классы `ym-disable-keys` и `ym-hide-content`; экран «спасибо» |
| E18 | Оценка: восторг → причины → «спасибо» | `detail` только с тегами; ссылка на Карты из `config`; клик — шаг `review_click` |
| E19 | Смена эмоции после отправки | `POST /api/feedback/rate`; `locked` и `expired` показывают текст сервера |
| E20 | `feedback` → `not_claimed` | Текст сервера |
| E21 | Клавиатура в оценке | Стрелки, Home и End на слайдере; фокус заперт в диалоге; Esc закрывает; фокус возвращается |
| E22 | Табло | Колонки по статусам, свой номер — `mine` (кольцо + «ваш»). Тап по чужому номеру ничего не делает |
| E23 | Таб-бар и переключатель | Правила центральной кнопки ([01-product.md](01-product.md) §10); точка «Новое» при смене статуса на другом экране; кнопки доступны без связи |
| E24 | Помощь | Ссылки только из `config`; нет ссылки — нет кнопки; строка про Instagram на месте |
| E25 | Потеря связи | Опрос падает → по флагу `guestOfflineAfterMs` экран «Нет связи». Восстановление → экран оживает, один отчёт `offline` с длительностью, троттлинг 60 с |
| E26 | Скрытая вкладка | Интервал 20 с; при возврате — немедленный опрос; запросы не накладываются (в полёте не больше одного) |
| E27 | Бэкофф гостя | 5 / 10 / 20 / 40 / 60 с при сбоях подряд, сброс после успеха |
| E28 | Две вкладки | Подписка в одной вкладке видна в другой (событие `storage`) |
| E29 | Legacy-маршруты | `/tv`, `/staff`, `/stats` показывают legacy, нет ошибок CSP, Метрика не инициализирована |
| E30 | Совместимость записи | Запись в формате legacy → новый фронт показывает правильное состояние |
| E31 | Глубокая ссылка `/board?my=1` | Без записи — ввод номера; с записью — заказ |
| E32 | Кнопки «назад» и «вперёд» браузера | Переходы между экранами по истории |
| E33 | Метрика | `hit` на каждую смену экрана без дублей; цели без токенов |

## 8. Визуальная регрессия

- Эталоны — для каждого экрана и состояния на ширинах из Figma, а также витрина компонентов (`dev/kit.html`).
- Эталоны генерируются **только** в CI, в официальном Docker-образе Playwright той же версии, что `@playwright/test`. Иначе шрифты рендерятся по-разному.
- Снимки делаются после `document.fonts.ready`, с маской для динамики (время `now`).
- Порог: `maxDiffPixelRatio: 0.002`.
- Новый эталон принимается только после сверки с Figma по критериям [05-figma-workflow.md](05-figma-workflow.md) §5 — решение за Claude Code.
- Агент эталоны не коммитит. CI на PR генерирует недостающие (`--update-snapshots=missing`) и выкладывает их артефактом. Claude Code сверяет их с кэшем Figma и коммитит утверждённые.

## 9. Доступность

- **Автоматически:** `eslint-plugin-jsx-a11y`, проверки ролей и подписей в RTL, клавиатурные e2e (E21, E23).
- **Вручную** перед релизом:
  - VoiceOver в iOS Safari и TalkBack в Android Chrome на сценарии «подписка → готово → оценка»;
  - объявление смены статуса;
  - масштаб текста 200 %;
  - альбомная ориентация.
- **Контраст** обеспечивают токены. Новые сочетания «текст / фон», которых нет в Figma, не вводятся.

## 10. Интеграция с настоящим бэкендом (Claude Code)

1. Поднять основной репозиторий локально по README. Собрать образ с нашим `dist/` во `frontend/` (временная ветка).
2. `poetry run python scripts/progon.py` — все сценарии зелёные: они проверяют раздачу экранов, кассу, отзывы, аналитику.
3. `npm run test:e2e:real` создаёт собственный ephemeral Docker backend с синтетической БД на loopback, а не подключается к чужому работающему серверу. Реализован ограниченный набор: HTTP contracts/limiter, 4 rating + 2 live-status flow, 18 legacy/CSP tests; exact pin и prerequisites — [31-local-integration-runner-2026-10-08.md](31-local-integration-runner-2026-10-08.md). Это пока не вся матрица E01, E02, E11–E19, E22, E29 и не приёмка W5-5. Хелпер входит/выходит только из собственной синтетической кассы; контейнер удаляется после результата или обычной ошибки.
4. Проверить в журнале контейнера, что нет неожиданных 4xx и 429 от нашего фронта.

## 11. Реальные устройства (перед каждым MINOR и MAJOR релизом)

- iPhone, актуальная iOS: Safari и браузер внутри Telegram.
- Android, актуальный Chrome: браузер внутри Telegram, открытие ссылки из приложения «Камера» или сканера QR.
- Планшет (вид ≥ 768).
- С фазы 6 — ТВ в зале. Проверка вживую, издалека, в течение смены.

## 12. Производительность и размер

- Бюджеты — [02-architecture.md](02-architecture.md) §17. `npm run check:size` считает gzip-размер JS до первого экрана (входной скрипт, `mount-*` и их статические импорты) и отдельно сумму ленивых чанков, gzip-размер CSS и размер главного фото. Обе цифры печатаются в выводе. Превышение валит CI.
- Перед релизом — ручной замер LCP и CLS в Chrome DevTools с троттлингом «Fast 4G» и замедлением CPU ×4.
- **Нагрузка.** Цель «100 одновременных гостей» — сценарий для согласованной тестовой среды, не прод. Инструмент нагрузки выбирается отдельным ADR.

## 13. Ворота CI

PR не мёржится, пока не зелёные: `typecheck`, `lint`, `check:tokens`, `test` (с порогами покрытия), `build`, `check:size`, `test:e2e` (все проекты), `npm audit --omit=dev --audit-level=high`.
