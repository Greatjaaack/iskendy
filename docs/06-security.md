# 06 · Безопасность

Бэкенд уже защищает себя: CSP, лимиты, закрепление номера за телефоном, один отзыв на заказ, одна сессия кассы. Задача фронта — не ослабить эту защиту, не создать новых дыр и не утечь данными гостя.

## 1. Модель угроз

| Угроза | Где | Чем закрыто |
|---|---|---|
| Чужая оценка за заказ (номер виден всему залу на ТВ) | Гостевой путь | Сервер: claim + `claimToken`. Фронт: ключ хранится только локально, никуда не передаётся, кроме `POST /api/feedback` |
| Захват номеров впрок, подписки пачкой | Подписка | Сервер: лимиты и алерт. Фронт: claim только по действию гостя, без фоновых повторов |
| XSS через данные гостя или ссылки | Везде | React экранирует текст. Запрет `dangerouslySetInnerHTML`, `innerHTML`, `eval`. Ссылки только `https:` и только из конфигурации сервера |
| Утечка токенов и персональных данных в аналитику и логи | Метрика, `client/event`, консоль | Явные запреты (§3), классы Метрики, троттлинг и очистка `detail` |
| Отказ в обслуживании зала из-за лимитов | Общий IP зала | Минимум запросов, обход BUG-01 ([03-api-contract.md](03-api-contract.md) §4) |
| Подмена фронта при поставке | Релиз | Контрольная сумма архива, `ADD --checksum` в патче `Dockerfile` |
| Уязвимые зависимости | Сборка | Lockfile, `npm ci`, `npm audit`, только согласованные пакеты |
| Встраивание страницы (кликджекинг) | — | Сервер: `X-Frame-Options: SAMEORIGIN`, `frame-ancestors 'self'` |
| Утечка кода и деталей через карты исходников | Прод | `sourcemap: false` |

## 2. Совместимость с CSP (бэкенд не меняем)

Разрешено только:
- скрипты своего origin и `https://mc.yandex.ru`;
- стили своего origin (и Google Fonts, но мы их не используем);
- шрифты своего origin;
- картинки своего origin, `data:` и `mc.yandex.ru`;
- `fetch` к своему origin и `mc.yandex.ru`.

Следствия:
1. Никаких CDN: всё, включая шрифты (@fontsource), — в сборке.
2. Никакого WASM (нет `wasm-unsafe-eval`).
3. Видео и аудио — только со своего origin. Звук «Готово» синтезируется WebAudio, файлы не нужны.
4. Хотя `'unsafe-inline'` разрешён, новый код не использует инлайновые скрипты и обработчики в HTML: всё в модулях. Это задел, чтобы владелец мог убрать `'unsafe-inline'`, когда legacy уйдёт целиком.

## 3. Данные: что можно и что нельзя

| Данные | Хранить | Отправлять |
|---|---|---|
| `iskendy_guest` (метка устройства) | `localStorage` (как legacy) | В `claim` и `guest/event` |
| `iskendy_visit` (метка визита) | `sessionStorage` | В `guest/event` |
| Номер своего заказа | В журнале `iskendy_orders_v1:*`, проекции `iskendi_my_order` и `iskendy_selected_order_v1` (ADR-019) | В API заказа, `guest/event`; в Метрику — нет |
| `claimToken`, `editToken` | Только в журнале `iskendy_orders_v1:*` и проекции `iskendi_my_order` (ADR-019) | Только в соответствующие эндпоинты отзывов. **Никогда** в URL, query, Метрику, `client/event`, консоль |
| Комментарий, контакт | **Не хранить** (только в состоянии формы до отправки) | Только `POST /api/feedback/detail` |
| Ответ `feedback/rate.feedback` | Не хранить | — |
| JWT кассы `iskendy_staff_token` | Не трогать до фазы 8 | — |

## 4. Яндекс.Метрика и вебвизор

- Инициализация только на `/` и `/board`. На `/tv`, `/staff`, `/stats` Метрики нет: это решение legacy, оно сохраняется.
- Вебвизор записывает экран. Поэтому:
  - поля комментария и контакта — класс **`ym-disable-keys`**: ввод заменяется звёздочками;
  - контейнеры формы отзыва с введённым текстом — класс **`ym-hide-content`**;
  - пароля кассы в новом фронте нет. В фазе 8 поле пароля — `type="password"`, Метрики на `/staff` нет.
- В параметры целей (`reachGoal`) не передавать токены, номер заказа, комментарии, контакты.

## 5. Ссылки и внешние переходы

- Ссылки на Яндекс Карты, 2ГИС, Telegram, VK, Instagram — только из `GET /api/feedback/config`. Перед выводом проверить через `new URL()`, что протокол `https:`. Иначе кнопку не рисовать.
- Внешние ссылки открываются с `rel="noopener noreferrer"`. `target="_blank"` — только где так в макете.
- Произвольные URL из данных пользователя никогда не становятся ссылками.

## 6. Лимиты и вежливость к серверу

- Подписка (claim) — только по нажатию. Повторы — строго по ADR-005.
- На 429 автоповтора нет, гостю — понятный текст.
- Отчёты экрана — не чаще раза в 60 с и не во время подписки (BUG-01).
- Нагрузочные проверки — только в согласованной тестовой среде, не на проде. Цель «100 одновременных пользователей» — сценарий проверки, а не обещанная ёмкость.

## 7. Зависимости и поставка

- Только согласованные пакеты (ADR-001). Новый пакет — ADR с обоснованием, проверкой лицензии, размера, числа транзитивных зависимостей, наличия install-скриптов.
- `npm ci` по lockfile. В CI — `npm audit --omit=dev --audit-level=high`, при находке сборка падает. Исключение — только записанное в ADR.
- Обновление зависимостей — отдельные PR с прогоном всех тестов.
- Релизный архив публикуется с `sha256`. В патче `Dockerfile` загрузка архива проверяется `ADD --checksum=sha256:…` ([08-delivery.md](08-delivery.md) §4).
- Секретов во фронте нет и быть не может. Токены GitHub — только в секретах CI.

## 8. Ошибки и отчёты

- Отчёт `client/event`: `kind` (`offline` | `render` | `js`), `screen` (имя экрана, не URL с query), `detail` — сообщение ошибки, обрезанное до 300 символов, без значений из хранилища и тел запросов.
- В проде нет `console.log` с данными. Перед отправкой отчёта stack trace обрезается.

## 9. Чек-лист безопасности для ревью

- [ ] Нет `dangerouslySetInnerHTML`, `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `eval`, `new Function`, `setTimeout(string)`.
- [ ] Нет `http://` и внешних доменов, кроме `mc.yandex.ru` в модуле аналитики.
- [ ] `localStorage` и `sessionStorage` — только в `src/storage/`.
- [ ] Токены не попадают в URL, Метрику, отчёты, консоль.
- [ ] Поля отзыва помечены `ym-disable-keys` и `ym-hide-content`.
- [ ] Внешние ссылки проверены (`https:`) и с `rel="noopener noreferrer"`.
- [ ] Повторы запросов соответствуют таблице идемпотентности ([02-architecture.md](02-architecture.md) §10).
- [ ] `sourcemap: false`, в `dist/` нет `.map`.
