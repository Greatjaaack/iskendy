# 10 · Решения (ADR) и открытые вопросы

Решения ADR-001…ADR-006 приняты в споре двух моделей 07.10.2026 и сверены с кодом бэкенда. Новое решение — новый ADR в конце списка. Пересмотр — новый ADR, который отменяет старый; старые не удаляются.

**Статусы:** «Принято», «Предложено» (можно оспорить до начала работ по нему), «Требует проверки» (решение зависит от спайка).

## Решения

### ADR-001 · Стек и список разрешённых пакетов — Принято

**Контекст.** Бэкенд не меняется, CSP строгий, нужен статический фронт с качественной AI-генерацией кода и экосистемой владельца.

**Решение.** React 19 + TypeScript strict + Vite, React Router, TanStack Query, Zod, CSS Modules + токены из Figma, Radix Dialog и Slider, vite-imagetools, @fontsource, Vitest + RTL + MSW, Playwright, ESLint + Prettier. Next.js, SvelteKit, Solid и Tailwind рассмотрены и отклонены.

**Полный список пакетов.** Всё остальное — только через новый ADR.

### ADR-002 · Отдельный репозиторий и поставка версионированным архивом — Принято

**Решение.** Фронт живёт в своём репозитории. CI публикует `iskendy-web-X.Y.Z.tar.gz` + `sha256` в GitHub Releases. В основной репозиторий архив попадает патчем `Dockerfile` (вариант A) или коммитом файлов (вариант B) — [08-delivery.md](08-delivery.md) §4.

**Следствие.** Способ интеграции выбирает владелец основного репо (Q-11). Патч `Dockerfile` — предложение, а не обязательная часть нашей работы.

### ADR-003 · Загрузчик с переключением маршрутов на legacy — Требует проверки (W0-7)

**Контекст.**
- Бэкенд отдаёт один `index.html` на все пять экранов, поэтому выкатка по частям без правки инфраструктуры невозможна.
- Правка общего Caddy дорогая: он обслуживает соседние стеки, а сторож сверяет его с git.
- Старый клиент выбирает экран по `location.pathname`, поэтому просто открыть `/legacy.html` не получится — будет лендинг.

**Решение.** Новый `index.html` — загрузчик. Для маршрутов `app` монтирует приложение. Для маршрутов `legacy` загружает `/legacy.html` и подменяет им документ (`document.open/write/close`) на том же URL — старый клиент видит свой путь. Таблица маршрутов — `src/boot/routes.ts`.

**Следствия.** Поэкранная выкатка, `/tv` остаётся на legacy до проверки браузера ТВ, откат маршрута без деплоя бэкенда.

**Запасной путь, если спайк не пройдёт:** выпуск только целиком, после переноса всех экранов. Откат — на предыдущий архив.

**Спайк на Mac, 2026-10-08.** Автоматические проверки загрузчика, CSP FastAPI,
локальной авторизации/графиков и регистрации sw.js зелёные. Переходы через
границу app/legacy теперь вызывают reload того же URL через route-handoff.ts;
pushState/replaceState/popstate и query сохраняются. Снимок legacy не изменён.
Статус остаётся «Требует проверки» до ручной приёмки и физических телефонов.
Доказательства и условия перехода: [15-mac-review.md](15-mac-review.md).

### ADR-004 · Опрос табло — Принято

**Решение.**
- Один владелец опроса на ресурс, единый `queryKey ['board']`; потребители — `enabled: false`.
- Интервал 5 с при видимой вкладке, 20 с при скрытой (`refetchIntervalInBackground: true`).
- Внутренних повторов нет (`retry: 0`): следующий тик и есть повтор.
- У каждого запроса `AbortSignal` и таймаут 6 с, запросы не накладываются.
- Сбои подряд считаются явно, только по завершённым запросам.
- Бэкофф раздельный: гость и ТВ — 5 / 10 / 20 / 40 / 60 с; касса — потолок 10 с (одно устройство, восстановление важнее нагрузки).
- Плашка кассы — после 2 сбоев подряд, без задержки.

### ADR-005 · Политика `claim` — Принято

**Контекст.** `db.claim_order` для того же `guest` возвращает тот же `claimToken` — запрос идемпотентен. Лимит — 10 в минуту на IP всего зала.

**Решение.**
- `claim` только по действию гостя.
- Один автоповтор после таймаута или сетевой ошибки с тем же `guest`.
- Без повтора на 429 и на `ok:false`.
- Если подписка прошла без ключа, перед первой оценкой — один `claimEnsure`.

### ADR-006 · API-слой: fetch + Zod по эндпоинтам — Принято

**Решение.**
- Своя обёртка над `fetch`.
- Отдельная Zod-схема на каждый ответ, без общего «конверта».
- Бизнес-ошибки (`ok:false` при HTTP 200) — часть данных.
- Общий слой нормализации сетевых и HTTP-ошибок: таймаут, 401, 409, 422 с массивом `detail`, 429, 5xx не-JSON.
- Схемы проверяются реальными фикстурами.
- Генератор типов из OpenAPI не используется: ответы бэкенда не описаны.

### ADR-007 · Стили: CSS Modules + токены, сгенерированные из Figma — Принято

**Решение.**
- Токены экспортируются из Figma в JSON и генерируются в CSS-переменные ([04-design-system.md](04-design-system.md) §9).
- Компоненты используют только семантические токены, отступы и радиусы. Используется ровно та переменная, к которой привязан узел в Figma.
- Сырые цвета и примитивы в компонентах запрещены, проверяет `check:tokens`.

### ADR-008 · Radix только для Dialog и Slider — Принято

**Решение.** Точечно `@radix-ui/react-dialog` (фокус, Esc, возврат фокуса, блокировка прокрутки) и `@radix-ui/react-slider` (`role="slider"`, клавиатура). Стилизация — CSS Modules и токены. Библиотек компонентов и дизайн-систем нет.

### ADR-009 · Иконки через CSS-маску из исходных SVG — Предложено

**Решение.**
- SVG из библиотеки `icons` скачиваются через Figma MCP без изменений.
- Рисуются как `mask-image` с `background-color: currentColor`.
- Без SVGR (новая зависимость), без вставки разметки SVG в DOM, с сохранением исходных файлов.

### ADR-010 · Раскладка сборки — Принято

**Решение.**
- `assetsDir: 'app'`, чтобы не пересекаться со старой папкой `assets/`.
- Без карт исходников.
- Legacy-файлы копируются в сборку.
- Архив без корневой папки, с `VERSION` и `ROUTES.json`.

### ADR-011 · Движение только в фазе 7 и только GSAP — Принято

**Решение.**
- До фазы 7 никакой анимации и CSS-переходов, смены состояний мгновенные, визуал — статичные изображения.
- В фазе 7 — GSAP + `@gsap/react` (без WASM и `eval`, совместим с CSP), лениво загружаемым чанком, с обязательной поддержкой `prefers-reduced-motion`.
- Спецификация движения утверждается Максимом до старта фазы.

### ADR-018 · GSAP Loader/Ticker — Авторизовано владельцем 2026-10-09

Технология GSAP ранее одобрена; повторное указание владельца продолжать реализацию передано через родительскую задачу. Только gsap@3.15.0 и @gsap/react@2.1.2, exact versions из official registry. Core/CSSPlugin/useGSAP, без новых plugins/ScrollTrigger/all/CDN. Разрешены только Loader360°/1.1с linear и Ticker60px/s с duration по фактическому cycle width. Dynamic import после static render; cleanup/matchMedia, visibility pause, accessible static fallback. Reduced motion **полностью статичен** в этом проходе, без breathing; персонажи и TV статичны. Позднее20:28UTC владелец явно расширил проход на button press120–150ms scale0.98, Slider160ms power2.out и CompactDock180ms по высоте панели; reduce instantaneous, focus/keyboard сохраняются. Status/Dialog/Steps/Popup/Float этим ADR не разрешены. ALL включает GSAP chunk; gate не ослабляется, исходный144004/122880 уже FAIL. Установка требует честного delta/audit/CSP/ordinary+reduce E2E; ADR не является релизной приёмкой.

**Дополнение 2026-10-12 (Максим, при ревью).** Разрешён ещё один эффект: выдвигание карточки заказа из стопки «Мои заказы» (подача «как Wallet», docs/reviews/2026-10-12-orders-navigation.md §9). Только transform/opacity, около 250 мс, тот же ленивый GSAP-чанк, при `prefers-reduced-motion: reduce` — мгновенно; фокус и клавиатура не ждут анимацию. Параметры движения утверждаются в Figma вместе с макетом стопки. Остальные ограничения ADR-018 не меняются.

**Дополнение 2026-10-13 (Максим).** Нижние листы («Добавить заказ», подтверждение «Убрать заказ») смахиваются вниз: сверху ручка 40×5, лист следует за пальцем; отпускание ниже трети высоты или быстрый жест вниз закрывает, иначе лист возвращается. Возврат и закрытие ≈ 200 мс, transform; при `prefers-reduced-motion: reduce` — без анимации. «×», Esc и тап по затемнению закрывают так же; фокус возвращается на кнопку-источник.

**Лицензия (2026-10-12, Максим).** `gsap` и `@gsap/react` распространяются по GSAP Standard «no-charge» License (Webflow): коммерческое использование разрешено, запрет — только на продукты, конкурирующие с Webflow. Лицензия принята.

### ADR-012 · Совместимость хранилища с legacy — Принято

**Решение.**
- Ключи и форматы прежние: `iskendy_guest`, `iskendi_my_order` (`localStorage`); `iskendy_visit` (`sessionStorage`).
- Неизвестные поля записи сохраняются; запись — патчем к актуальной версии.
- Совместимость в обе стороны покрыта тестами.
- `iskendy_staff_token` не трогаем до фазы 8.

**Следствие.** Откат посреди заказа не ломает гостю экран.

### ADR-014 · Ссылка на Яндекс Карты — всем гостям — Принято (по макету D5)

**Контекст.** Legacy показывал ссылку только при оценке 4–5. В макете D5: «Предлагаем всем гостям, без бонусов за отзыв — таковы правила Яндекса».

**Решение.** Ссылка из `/api/feedback/config` показывается в «спасибо» обеих веток, независимо от оценки. Бэкенд это позволяет: `config` отдаёт ссылки всем.

**Уточнение 2026-10-12 (Максим).** На экране «Выдан» ссылки нет: там главная задача — оценка. В негативной ветке ссылка стоит под строкой «Управляющий уже получил ваш отзыв.».

### ADR-015 · Отчёты экрана: 60 с и тишина во время подписки — Принято

**Контекст.** BUG-01: `client/event` и `guest/claim` делят корзину лимита `c`.

**Решение.** Отчёты не чаще раза в 60 с с устройства, только после восстановления связи или при ошибке, никогда во время подписки. Владельцу бэкенда предложено исправление (Q-12).

### ADR-016 · Ночная работа облачного агента по кэшу Figma — Принято

**Контекст.**
- Ночью компьютер выключен, код пишет облачный агент.
- В облачной задаче нет интернета во время работы агента и нет Figma MCP.
- Лимит MCP на чтение — 200 вызовов в день на тарифах Pro и Organization.

**Решение.** Правила — в [12-night-mode.md](12-night-mode.md):
- облачная среда без интернета для агента и без секретов;
- данные Figma заранее снимает через MCP Claude Code в кэш `design/figma/`;
- `package.json` заморожен после W0-1;
- за ночь не больше трёх задач, у каждой зависимости уже в `main`;
- эталонные скриншоты коммитит Claude Code;
- плагины процесса (Superpowers и подобные) не используются.

**Следствия.** Ночью сверка с Figma идёт по снимку. Живую сверку утром делает Claude Code. При изменениях в Figma кэш нужно переснять.

### ADR-017 · Сравнительный эксперимент с Terser — Эксперимент завершён; постоянная смена не принята

**Основание.** AGENTS.md §3, правило 5 требует новый ADR **и одобрение
Максима** для любой новой зависимости, включая dev. Terser отсутствует в
ADR-001. Статус «Предложено» сам по себе не даёт разрешения на установку.
Максим ответил «по коду продолжай разработку» на конкретный вопрос
о Terser, пределах и рисках. Родительский агент подтвердил разрешение
на ограниченный обратимый эксперимент (15:13 UTC), не смену всего стека.

**Контекст.** Baseline `4d9dafc1828e1d9e41cc7691e82fff5780e54833`:
ALL JS 137772 Б gzip, лимит 122880 Б, превышение 14892 Б. Oxc остаётся
текущим минификатором; измерения безопасного tree-shaking — docs/32.

**Предложение для решения владельца.** Разрешить один обратимый локальный
эксперимент: добавить точно `terser@5.51.2` в devDependencies и lockfile из
официального npm registry и сравнить Vite `build.minify: 'terser'` с Oxc
в той же ветке. Версия/Node engines получены read-only `npm view` 2026-10-08.
Terser используется только при сборке и не является клиентской библиотекой.

В эксперименте сохранить Safari15/Chrome100 target, checker ALL JS, все
функции, UI, accessibility, API/storage/claim и lazy Rating. Использовать
обычную безопасную compression, `unsafe: false`; не применять property
mangling, `pure_funcs`, drop-console или иные допущения о побочных эффектах.
Приватный код не отправляется внешним сервисам; npm получает только запросы
метаданных и официальных пакетов. Нет push/deploy.

**Проверка и критерий.** Сравнить все gzip chunk sizes, обязательный граф
первого экрана и время сборки с указанным baseline. Проверить `npm audit`
для добавленного build tooling, полный verify (либо отдельно E2E, если size
останавливает pipeline), реальную синтетическую Docker integration и progon
на итоговой конфигурации. Принять минификатор только после фактического
улучшения и тестов; заранее достижение 120 КиБ не обещается. Без результата
откатить package/lock/config к baseline, сохранив измерения в evidence.

**Риски.** Новые транзитивные зависимости и их supply-chain; другое
преобразование JS может дать регрессию даже без unsafe опций; сборка может
стать медленнее. Поэтому нельзя объявить смену безопасной по одному замеру.

**Результат эксперимента.** Стандартный Terser хуже Oxc; безопасные три
прохода с ES2020 дают 137148 Б против 137772 Б Oxc (−624 Б, 0.45%).
Пять/десять проходов не улучшают ALL дальше. В локальной кандидатной сборке
выбран Terser с тремя проходами; build медленнее примерно на 2 с в одиночном
замере. Size остаётся FAIL. Полные проверки и ограничения — docs/33.
2026-10-09: gain 624 Б недостаточен при +2153 мс в замере; текущие
package/lock/Vite возвращены к Oxc baseline 4d9dafc, experiment be93bf3
сохранён без изменения истории. Диагноз — docs/34. Это не разрешение
на другие зависимости или формальная приёмка фазы.

### ADR-019 · Журнал заказов гостя (мультизаказ) — Принято 2026-10-12

**Контекст.** Согласованный мультизаказ (docs/38–40) добавил ключи `iskendy_orders_v1:<id>` (операция на ключ) и `sessionStorage.iskendy_selected_order_v1` без ADR. Журнал не удалял записи: ~7 ключей на заказ, заметные подвисания при сотнях ключей (ревью 2026-10-12, SEC-01, CODE-05).

**Решение (Максим, 12.10).** Заменяет ADR-012 в части ключей; совместимость с legacy сохраняется.
- Ключи: журнал `iskendy_orders_v1:*`, выбранный заказ вкладки `iskendy_selected_order_v1`, `iskendi_my_order` — проекция для отката на legacy. `iskendy_guest`, `iskendy_visit` без изменений; `iskendy_staff_token` не трогать.
- Срок хранения — **текущий деловой день** по `date` из `/api/status` (не часы телефона). Записи прошлых дней удаляются при первом успешном опросе.
- Уплотнение: когда ключей журнала больше 20, они сворачиваются в один снимок без потери параллельных записей второй вкладки.
- «⋯ → Убрать из моих заказов» удаляет заказ локально; квоту бэкенда (5 номеров в день) это не возвращает, интерфейс об этом говорит.
- `claimToken` и `editToken` допустимы в журнале и в проекции; наружу (URL, Метрика, `client/event`, консоль) не уходят — docs/06 §3 обновить.


### ADR-020 · Свой маршрутизатор вместо react-router — Принято 2026-10-13

**Контекст.** Первый экран упёрся в бюджет: 119,78 КБ из 120 КБ gzip (docs/02 §17, решение 12.10). Замер 13.10: `react-router` весит ≈ 13,9 КБ gzip, а гостевому фронту нужны два адреса (`/`, `/board`) с параметрами, переходы, «Назад»/«Вперёд» и ссылка. Состояние перехода (`location.state`) не используется. Заменить можно только роутер: React, react-query и Zod нужны.

**Решение (Максим, 13.10: «делай B»).** Удалить зависимость `react-router` и заменить её модулем `src/app/router.tsx` (~1 КБ): `useLocation()` (путь и строка запроса из `window.location`, подписка на `popstate`), `useNavigate()` с `{ replace }`, `<Link>` с обычным `<a href>` (клик с модификаторами, средней кнопкой или `target` не перехватывается). История — `history.pushState/replaceState`, поэтому переход между новым фронтом и legacy (`src/boot/route-handoff.ts`) работает как раньше. Порог первого экрана остаётся 120 КБ.

**Последствия.** Нет вложенных маршрутов, загрузчиков и восстановления прокрутки — они не нужны двум экранам. Если адресов станет больше, вернуться к библиотеке через новый ADR. В тестах `MemoryRouter` заменён на `history.replaceState`.
