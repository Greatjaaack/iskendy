# 08 · Поставка: CI, релизы, интеграция, деплой, откат

## 1. Репозитории и роли

| Репозиторий | Что в нём | Кто пишет |
|---|---|---|
| `iskendy-web` (этот, рабочее имя; размещение — Q-22) | Новый фронт, снимок legacy, документация | Codex — ветки и PR; Claude Code — мерж, релизы |
| `Greatjaaack/iskendy` (основной) | Бэкенд, `frontend/` (то, что отдаёт FastAPI), `Dockerfile`, деплой | Codex — **только чтение**. Claude Code — ветки и PR с интеграцией, мерж **только с одобрения владельца** |

## 2. Ветки, PR, CI

- `main` защищён: только через PR, обязательны зелёные проверки CI (ворота — [07-testing.md](07-testing.md) §13), мерж squash.
- Ветки Codex: `feat/<id>-<slug>`, `fix/<id>-<slug>`. Ветки Claude Code: `chore/release-x.y.z`, `chore/legacy-sync-<commit>`.
- **`ci.yml`** — на каждый PR и пуш в `main`:
  1. `npm ci`;
  2. `npm audit --omit=dev --audit-level=high`;
  3. `typecheck`, `lint`, `check:tokens`;
  4. `test` с покрытием;
  5. `build`, `check:size`;
  6. `test:e2e` в официальном образе Playwright;
  7. артефакты: отчёт Playwright, диффы скриншотов, `dist/`.
- **`release.yml`** — на тег `v*`: `npm ci`, `build`, `assemble-release`, публикация GitHub Release с архивом и `.sha256`.
- Версия Node — актуальная LTS, зафиксирована в `.nvmrc` и `engines`.

## 3. Релиз и состав архива

Версии — semver ([`CLAUDE.md`](../CLAUDE.md) §5). Архив `iskendy-web-X.Y.Z.tar.gz` **без корневой папки** — распаковывается прямо во `frontend/`:

```
index.html     новый: загрузчик (src/boot) + приложение
legacy.html    снимок старого frontend/index.html, байт в байт
sw.js          service worker уведомлений (контракт legacy)
app/           бандлы, CSS, шрифты, изображения нового фронта (имена с хэшем)
assets/        файлы legacy: favicon.png, logo_white.png, iskendi_wordmark_white.png
VERSION        X.Y.Z, коммит, дата сборки
ROUTES.json    какие маршруты на новом фронте, какие на legacy (для людей и смоука)
```

Рядом лежит `iskendy-web-X.Y.Z.tar.gz.sha256`. Карт исходников (`.map`) в архиве нет.

## 4. Интеграция с основным репозиторием

Способ выбирает владелец основного репозитория (Q-11). Оба варианта не трогают код бэкенда.

### Вариант A (рекомендуемый) — патч `Dockerfile`: архив скачивается при сборке

```dockerfile
# syntax=docker/dockerfile:1.7
# --- фронтенд: релиз iskendy-web (версия и контрольная сумма закреплены) ---
FROM alpine:3.20 AS web
ADD --checksum=sha256:<SHA256_АРХИВА> \
    https://github.com/<ORG>/iskendy-web/releases/download/vX.Y.Z/iskendy-web-X.Y.Z.tar.gz \
    /tmp/web.tgz
RUN mkdir /web && tar -xzf /tmp/web.tgz -C /web

FROM python:3.12-slim
# … без изменений до строки с фронтом …
COPY backend/ ./backend/
# было: COPY frontend/ ./frontend/
COPY --from=web /web/ ./frontend/
# … дальше без изменений …
```

- Версия и контрольная сумма пишутся в `Dockerfile` **литералами**: каждая смена версии — отдельный PR. При несовпадении суммы сборка падает — так защищена цепочка поставки.
- Нужен BuildKit с поддержкой `ADD --checksum`: проверить сборкой на сервере до первого релиза.
- Если репозиторий фронта приватный, сервер не скачает архив без токена (Q-22). Тогда — вариант B, либо публичные релизы.
- Папка `frontend/` в основном репозитории после этого не используется при сборке. Её стоит оставить с README «собирается из iskendy-web».

### Вариант B (запасной) — собранные файлы коммитятся во `frontend/`

Claude Code распаковывает архив во `frontend/` основного репо и открывает PR `web: vX.Y.Z`. Плюс — ничего не меняется в `Dockerfile`. Минус — в git попадают сгенерированные файлы, а цепочку поставки защищает только ревью.

### Синхронизация legacy

- `legacy/` в этом репозитории — снимок `frontend/index.html`, `frontend/assets/*` и `frontend/sw.js` основного репозитория. Коммит и дата записаны в `legacy/SOURCE.md`. Стартовый снимок — коммит `7ab20f0` или более поздний на момент W0-2.
- **Перед каждым релизом** Claude Code сверяет снимок с текущим `frontend/` основного репо. Если там были правки (например, исправление кассы), — PR `chore/legacy-sync-<commit>` в этот репозиторий, затем релиз.
- После интеграции правки legacy-экранов (`/tv`, `/staff`, `/stats` до их фаз) вносятся **здесь**, в `legacy/`. Иначе следующий релиз их затрёт. Договорённость — часть Q-11.

## 5. Деплой

- По README основного репо прод обновляется из `main`: сервер делает `git pull` и пересобирает контейнер. Изменения, попавшие в `main`, уезжают на прод ближайшим ночным деплоем. Ускорить — только по договорённости с владельцем.
- **Порядок:**
  1. Релиз здесь.
  2. Интеграционная ветка в основном репо.
  3. Локальная сборка образа и `progon.py` ([07-testing.md](07-testing.md) §10).
  4. PR.
  5. Одобрение владельца.
  6. Мерж.
  7. Деплой.
  8. Смоук (§6).
- Не деплоить в пятницу вечером и перед праздниками — в эти дни нагрузка на точку выше.

## 6. Смоук-проверка после деплоя (прод, только чтение)

Делает Claude Code. Никаких подписок, оценок, входов в кассу.

1. `/` и `/board` открываются. В консоли нет ошибок JS и CSP, шрифты загружены.
2. `/VERSION` отдаёт нужную версию, `/ROUTES.json` совпадает с ожиданием.
3. Опрос `GET /api/status` — 200, раз в 5 с. В фоновой вкладке — раз в 20 с.
4. `/board?view=queue` и `/board?view=help` открываются, ссылки из `config` на месте.
5. `/tv`, `/staff` (экран входа), `/stats` (экран входа) открываются в legacy-режиме без ошибок.
6. `/sw.js` отдаётся с кодом 200.
7. Максим проверяет в Метрике (отчёт «в реальном времени»), что просмотры `/` и `/board` приходят.

**Наблюдение 48 часов:**
- журнал контейнера: строки `экран … offline/render/js`, всплески 4xx и 429;
- Telegram-темы аварий;
- воронка: доля `sub_ok` от `board_open` и число оценок в сравнении с прошлой неделей.

## 7. Откат

| Уровень | Когда | Как | Скорость |
|---|---|---|---|
| 1. Маршрут → legacy | Проблема на одном экране (например, `/board`) | Изменить `src/boot/routes.ts`, PATCH-релиз, интеграционный PR, деплой | Релиз + деплой |
| 2. Предыдущая версия | Проблема во всём релизе | Вариант A: вернуть в `Dockerfile` версию и сумму прошлого релиза. Вариант B: `git revert` интеграционного коммита | PR + деплой |
| 3. Полный возврат | Новый фронт неработоспособен | `git revert` первого интеграционного PR в основном репо — возвращает исходные `frontend/` и `Dockerfile` | PR + деплой |

Гостей посреди заказа откат не ломает: формат хранилища совместим с legacy в обе стороны (ADR-012).
