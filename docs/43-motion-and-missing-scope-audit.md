## Точные разрывы: игра, лента, TV

**Игра.** Нет GameTile компонента, ссылки «Играть», обработчика/маршрута игрового экрана, canvas engine, уровней или прогресса. gameTile=false в src/config/features.ts нигде не используется: просто поставить true недостаточно. App принимает orders/help/queue, игровой view не реализован. В legacy/index.html и frontend/backend проверенного reference готовая игра не найдена. Старые документы исключали её по Q-10; новое ожидание владельца учтено, исключение не является объяснением «готовности».

В Figma есть игра «Прыг до кассы»: page100:2, компоненты/уровни/mobile/desktop98:2…5. Game/Canvas100:7 — кадр прототипа с логическим480×512, не готовый engine. Controls100:8 задаёт удержание pointerdown/up и ПРЫГ; Dialog100:1810 — старт/ready/done/over, пауза+вибрация при реальном ready, звёзды за прохождение/без потерь/<80с, сохранение колец/чая при over. Минимальное восстановление включает настоящую 2D игру и лишь затем игровую плитку-переход. Нужны существующий исходник прототипа либо полная спецификация физики/уровней/прогресса из этих страниц; новую игру и backend API не придумывать. Возможный guest route через query на /board надо оформить в задаче, это пока предложение, не существующий маршрут.

**Лента.** Отсутствует весь Web/Ticker, а не только движение. Footer.tsx явно исключает W7; src/ui/Ticker и ticker content нет. Четыре исходных SVG звезды уже сохранены в src/assets/ticker. Минимум: сначала вернуть авторский блок и сообщения, затем GSAP цикл/reduce-вариант; картинка декоративной полосы сама по себе не заменяет контент.

**TV.** /tv в src/boot/routes.ts всё ещё legacy. Screenshot1920×1080 на синтетической очереди это подтвердил: без guest CompactDock, новый56:96 не подключён. Новый TV визуал авторизован владельцем и является самостоятельным этапом, а не масштабированным /board.56:96 содержит populated/empty/no-connection/overflow,1920×1080, две колонки, Rubik/Onest/акцент, overflow3×4 на колонку и минимум80% размера номера. Поправка: TV 768/* уже присутствовали в экспорте; недоставало только TV/* для 1920×1080. Они добавлены из текущего56:96 в следующем этапе. Требуется отдельно привязать TV styles/vars и проверить1920×1080/1366×768.

Сохранить один poller5с/20с и refresh на visibility return; hourly reload только после успешного /api/health; отсутствие гостевых Метрика/claim/rating. Figma no-connection убирает старые номера, legacy их сохраняет: реализация должна следовать назначенному56:96 и иметь явный проверенный триггер потери связи. Не скрывать готовые заказы по выдуманному N: Figma требует expiry после N минут, но такого параметра в прочитанном /api/status нет. Уточнить правило overflow и браузер Xiaomi; физическая совместимость пока не проверена. Backend не менять.

**Другие известные незакрытые части.** Popup/Float компонентов и motion-инфраструктуры нет. Системный notificationclick по-прежнему фокусирует первую /board или открывает /board?my=1 без order/day; конкретный фоновый заказ гарантирует только in-page readiness link. JS gate FAIL, ручная визуальная/физическая приёмка и ADR003 не завершены. Telegram-бот/подарок/контакт согласия — отдельные нерешённые контрактные вопросы Q-06/07/10, не работающие скрытые функции. /staff и /stats остаются legacy по текущему scope; их новый UI ещё не сделан.

## Зависимости, бюджет и необходимые решения

Только два пакета: gsap и @gsap/react. Read-only npm metadata9октября: кандидаты gsap3.15.0, @gsap/react2.1.2; peers у @gsap/react: gsap^3.12.5, react>=17. Это не установка/приёмка совместимости. Достаточны core+встроенный CSSPlugin и useGSAP; ScrollTrigger, GSAP all, Draggable, Flip, сторонний game engine не предлагаются. Версии/audit/lock фиксируются в dependency ADR перед установкой; выбор GSAP заново не обсуждается.

Выборочные imports и lazy загрузка технически предусмотрены публичным API [GSAP](https://gsap.com/docs/v3/Installation/), [React cleanup](https://gsap.com/resources/React/) и [matchMedia](https://gsap.com/docs/v3/GSAP/gsap.matchMedia()/). Они откладывают загрузку, но scripts/check-size.mjs суммирует **все** JS-чанки. Сейчас143173/122880, превышение20293. GSAP lazy chunk тоже будет посчитан; CDN/external/chunk exclusions не являются исправлением gate. Фактический delta не измерен без установки. Для принятия нужно сократить ALL минимум на20293 плюс измеренный прирост motion/game/TV. Без результата не обещать PASS или ослаблять checker.

Остались конкретные решения/данные, а не повторное одобрение GSAP:

1. Недостающие авторские параметры: Steps/status, кнопки/chips/slider/dialog и, если нужен, плавный CompactDock; opacity endpoints/easing loader и timings Popup/Float. Отдельно согласовать формулировку reduce: Figma loader breathing1,4с против общего «анимаций нет» в roadmap. До устранения противоречия текущий статичный reduce сохраняется.
2. Источник исполняемого игрового прототипа либо полные правила физики/уровней/прогресса; макет/карточка не доказывают наличие реализации.
3. Для TV — версия/UA реального браузера, правило переполнения сверх12 и N/expiry; выбранный56:96 повторно одобрять не требуется.
4. Dependency ADR с версиями и измеренный aggregate budget: lazy GSAP не закрывает уже существующий размерный блокер.

Остаток этапов: восстановить статичные Ticker и TV states, подготовить настоящее игровое ядро по исходникам; затем motion-обвязка/токены и эффекты с известными параметрами; далее обычный/reduce E2E, CSP/API/storage/legacy, размер/CLS и ручная приёмка на телефонах/TV. Это не срок, не релиз и не обещание100 одновременных гостей.
