# AGENTS.md — инструкция для Codex

Ты — **исполнитель** в проекте «Искенди · веб». Ты пишешь код и тесты по задачам из [`docs/09-roadmap.md`](docs/09-roadmap.md).

- **Claude Code** — приёмка: ревью, тестирование, визуальная сверка с Figma, релиз, деплой, пуш в GitHub ([`CLAUDE.md`](CLAUDE.md)).
- **Максим** — владелец продукта и дизайна. Отвечает на открытые вопросы и утверждает новые зависимости.

Всё ниже — обязательные правила, а не пожелания. Подробности — в [`docs/`](docs/00-index.md).

## 1. Что мы делаем

Гость дюрюмной «Искенди» сканирует QR на чеке, вводит номер заказа и видит путь заказа: **Принят → Готовим → Готово → Выдан**. Когда заказ готов, телефон звенит, вибрирует и показывает системное уведомление. После выдачи гость оценивает заказ эмоцией (1–5), может выбрать причины и написать управляющему. Есть общее табло очереди и экран «Помощь».

Бэкенд уже работает в проде и **не меняется**: <https://github.com/Greatjaaack/iskendy> (только чтение).

Новый фронт обслуживает `/` и `/board`. Экраны `/tv`, `/staff`, `/stats` до своих фаз работают на старом фронте через загрузчик (ADR-003).

## 3. Железные правила

### Бэкенд и окружение

1. Не менять бэкенд, его CSP, маршруты и `.env`. Не использовать эндпоинты и поля, которых нет в [`docs/03-api-contract.md`](docs/03-api-contract.md).
2. Фронт и API живут на одном origin. В коде только относительные пути `/api/...`. В разработке — прокси Vite.
3. Пути только `/` и `/board`, состояние экрана — через query (`/board?my=1`, `/board?view=queue`). Бэкенд отдаёт `index.html` лишь на `/`, `/board`, `/tv`, `/staff`, `/stats`, любой другой путь даст 404.

### Библиотеки

4. Только согласованные (ADR-001): React, TypeScript, Vite, TanStack Query, Zod, Radix UI (только Dialog и Slider), vite-imagetools, @fontsource, Vitest, React Testing Library, MSW, Playwright, ESLint, Prettier. В фазе 7 добавляются GSAP и @gsap/react. React Router удалён (ADR-020): маршруты — `src/app/router.tsx`.
5. Любая другая зависимость, включая dev, — только через новый ADR и одобрение Максима. Весь список ставится один раз в задаче W0-1. После неё `package.json` и lockfile меняются только по ADR.

### Дизайн

6. Каждый экран и компонент делается из Figma через Figma MCP (`get_design_context` со скриншотом), а не по памяти и не на глаз. Процедура — [`docs/05-figma-workflow.md`](docs/05-figma-workflow.md).
7. В CSS только CSS-переменные токенов.
   - Запрещены hex, rgb и hsl, именованные цвета, переменные примитивов `--brand-*` и `--prim-*`, «магические» px вне шкал `--space-*` и `--radius-*`.
   - Проверяет `npm run check:tokens`.
8. Используй ровно ту переменную, к которой в Figma привязан узел (её отдаёт MCP). Не «улучшай» роли токенов самостоятельно.
9. Тексты интерфейса берутся из Figma дословно и лежат в `src/content/`. Цена пишется как `300 ₽` с неразрывным пробелом, неизвестная — `— ₽`, не ноль.
10. **До фазы 7 никакой анимации**: ни `transition`, ни `@keyframes`, ни motion-библиотек, смена состояний мгновенная. Анимации из описаний компонентов в Figma реализуются в фазе 7 ([`docs/11-motion-gsap.md`](docs/11-motion-gsap.md)).
11. Изображения только статичные: фото, WebP персонажей, SVG иконок и орнамента. Чужие фото не подставлять.

### Поведение и данные

12. Опрос `/api/status` ведёт один владелец на всё приложение (ADR-004). Остальной код только читает кэш.
13. `POST /api/guest/claim` вызывается только по явному действию гостя (ADR-005).
    - Один автоповтор с тем же `guest` допустим только после таймаута или сетевой ошибки.
    - На 429 и на бизнес-ответы `ok:false` повтора нет.
14. Ключи хранилища и формат записей не меняются (ADR-012; журнал заказов и выбранный заказ — ADR-019).
    - `localStorage`: `iskendy_guest`, `iskendi_my_order`.
    - `sessionStorage`: `iskendy_visit`.
    - `iskendy_staff_token` не читать и не писать.
15. Названия шагов воронки (`/api/guest/event`) и целей Яндекс.Метрики не менять: это непрерывность аналитики.

### Безопасность ([`docs/06-security.md`](docs/06-security.md))

16. Никаких секретов в клиенте. `claimToken` и `editToken` не попадают в URL, логи, Метрику и `/api/client/event`.
17. Запрещены:
    - `dangerouslySetInnerHTML`, `eval`, `new Function`;
    - обработчики событий в HTML-атрибутах;
    - внешние скрипты, шрифты и картинки (единственное исключение — скрипт Метрики с `mc.yandex.ru`).
18. Поля комментария и контакта помечаются классом `ym-disable-keys`, их контейнеры — `ym-hide-content`.

### Процесс

19. Каждое изменение сопровождается тестами ([`docs/07-testing.md`](docs/07-testing.md)). Без тестов PR не принимается.
20. Одна задача — одна ветка — один PR.
21. Не мержить в `main`, не создавать релизы, не деплоить, не трогать основной репозиторий.
22. Без отдельной задачи не трогать `legacy/` (снимок старого фронта) и `public/sw.js`.
23. Ночью задачи выполняет облачный агент при выключенном компьютере. Действует [`docs/12-night-mode.md`](docs/12-night-mode.md):
    - нет интернета и Figma MCP — макеты только из кэша `design/figma/`;
    - `package.json` и lockfile не меняются;
    - вопросы задать некому: вариант по умолчанию за флагом или остановка на этой части.

## 4. Команды

| Команда | Что делает |
|---|---|
| `npm ci` | Установка строго по lockfile |
| `npm run dev` | Dev-сервер Vite, прокси `/api` → `http://localhost:8080` (локальный бэкенд) |
| `npm run dev:mock` | Dev-сервер с MSW вместо бэкенда |
| `npm run dev:kit` | Витрина компонентов (только в разработке, в сборку не попадает) |
| `npm run tokens` | `tokens/*.json` → `src/styles/tokens.css` и `src/styles/typography.css` |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run lint` / `npm run format` | ESLint / Prettier |
| `npm run check:tokens` | Запрет сырых цветов, примитивов и px вне шкал в CSS |
| `npm test` | Vitest: unit-тесты и тесты компонентов |
| `npm run test:e2e` | Playwright на MSW, все проекты-устройства |
| `npm run build` | Сборка `dist/`: новое приложение, загрузчик и legacy-файлы |
| `npm run check:size` | Бюджеты размера ([`docs/07-testing.md`](docs/07-testing.md)) |
| `npm run verify` | Всё перечисленное подряд. Должно быть зелёным перед PR |

Все скрипты заводятся сразу в задаче W0-1. Пока скрипт не реализован, он работает заглушкой: печатает «ещё не реализовано: W0-x» и завершается успешно. Реализуются скрипты в задачах фазы 0. Если заглушка мешает твоей задаче — это ошибка порядка работ, сообщи в PR.

## 5. Как выполнять задачу

1. Прочитай задачу в [`docs/09-roadmap.md`](docs/09-roadmap.md), связанные документы и открытые вопросы по теме.
2. Создай ветку `feat/<id>-<коротко>`, например `feat/w1-4-order-ticket`.
3. **Figma.** Днём, когда есть доступ к MCP, для каждого узла задачи:
   1. вызови `get_design_context` со скриншотом;
   2. если ответ помечен как sparse, запроси видимые дочерние узлы;
   3. вызови `get_variable_defs` на узле.

   Ассеты скачай в репозиторий через MCP. Временных ссылок Figma в коде быть не должно.

   **В облаке (ночью)** MCP недоступен. Те же данные лежат в кэше `design/figma/<nodeId>/`: `context.tsx`, `variables.json`, `screenshot.png`, `assets/` ([`docs/12-night-mode.md`](docs/12-night-mode.md) §4). Если узла в кэше нет, эту часть не делай и напиши об этом в PR.
4. Реализуй, переиспользуя компоненты из `src/ui/` и токены. Сделай все состояния варианта Figma (default, hover, pressed, focus, disabled, loading, error и т. д.).
5. Напиши тесты: unit и компонентные (Vitest + RTL + MSW), e2e и визуальные (Playwright) по матрице устройств.
6. Сверь визуально: Playwright-скриншот на ширине фрейма Figma рядом со скриншотом Figma. Расхождения исправь, оставшиеся объясни в PR.
7. Добейся зелёного `npm run verify`.
8. Открой PR по шаблону [`.github/pull_request_template.md`](.github/pull_request_template.md).

## 6. Definition of Done для каждого PR

- [ ] Сделано ровно то, что в задаче, и ничего сверх.
- [ ] Перечислены узлы Figma. Приложены пары скриншотов «Figma / реализация» на всех нужных ширинах.
- [ ] Используются только токены, `check:tokens` зелёный.
- [ ] Тексты взяты из Figma и вынесены в `src/content/`.
- [ ] Реализованы и проверены все состояния компонента или экрана из Figma.
- [ ] Клавиатура работает: Tab, Shift+Tab, Enter, Space, Esc, стрелки. Фокус виден и оформлен по токенам.
- [ ] Цели нажатия не меньше 44×44 px, у ползунка слайдера — не меньше 56 px.
- [ ] У каждой ошибки есть понятное состояние UI: сеть, таймаут, 4xx/5xx, 429, бизнес-ошибка `ok:false`.
- [ ] Добавлены тесты, `npm run verify` зелёный.
- [ ] Нет новых зависимостей без ADR.
- [ ] Документы обновлены, если изменилось поведение или решение.

## 7. Figma MCP

- Подключение: `codex mcp add figma --url https://mcp.figma.com/mcp`, затем авторизация в Figma и проверка через `codex mcp list`.
- Работа с Figma **только на чтение**. Ничего в файле не создавать и не менять.
- Если узел не привязан к переменной (сырое значение) или токен не имеет CSS-имени (`css`), не подбирай похожий токен. Это открытый вопрос (Q-13).
- В облачных задачах MCP недоступен — только кэш `design/figma/`. Кэш не редактировать: его снимает и обновляет Claude Code.

## 8. Структура репозитория (кратко)

```
AGENTS.md  CLAUDE.md  README.md
docs/                 документация
legacy/               снимок старого фронта (не редактировать)
public/sw.js          service worker уведомлений (контракт legacy)
tokens/               экспорт переменных и текстовых стилей из Figma
design/figma/         кэш данных Figma MCP для облачных задач (снимает Claude Code)
scripts/              генерация токенов, проверки, сборка релиза
src/boot/             загрузчик: новое приложение или legacy по маршруту
src/app/              роутер, провайдеры, ErrorBoundary
src/api/              клиент fetch, ошибки, Zod-схемы, эндпоинты
src/domain/           логика заказа и оценки (чистые функции)
src/storage/          единственный доступ к localStorage и sessionStorage
src/polling/          владелец опроса табло
src/platform/         уведомления, звук, вибрация, Метрика, отчёты экрана
src/ui/               компоненты Web/* из Figma
src/screens/          экраны: Entry, Order, Rating, Board, Help, Offline
src/content/          тексты и контакты из Figma, по файлу на экран или компонент
src/assets/           фото, иконки, персонажи, орнамент
src/styles/           токены (генерируются), типографика, глобальные стили
tests/                e2e, фикстуры, обработчики MSW
```

Подробно — [`docs/02-architecture.md`](docs/02-architecture.md).
